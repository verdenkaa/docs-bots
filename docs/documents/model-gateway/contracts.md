:::warning Рабочий контракт
Структуры фиксируют границу модулей. Значения профилей, пороги, провайдеры и численные лимиты выберем по кейсу; адаптеры ещё не реализованы.
:::

DTO — объекты Pydantic из `app/rag/model_gateway/contracts.py`. Все перечисленные поля обязательны; `None` передаём явно. Транспортный JSON конкретного провайдера наружу не выходит. [Точки входа](./entrypoints.md).

## Конфигурация роли {#binding}

`ModelRole = Literal["embedding", "reranker", "injection", "generation"]`. Runtime передаёт `Mapping[ModelRole, ModelBinding]` в `start_models`. Ключ задаёт роль, значение — один адаптер. Worker требует `embedding`; Core — `embedding`, `injection`, `generation` и `reranker`, если он включён в профиле поиска.

| Поле ModelBinding | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| `profile_id` | `str` | Непустой ID неизменяемого профиля: модель, версия, preprocessing, инструкции query/document и параметры вычисления. | `"embedding-v1"` |
| `execution` | `Literal["local", "remote"]` | Локальное вычисление в процессе либо сетевой вызов, включая собственный сервер модели. | `"remote"` |
| `provider` | `str` | Ключ зарегистрированного адаптера. Здесь нет выбранного по умолчанию провайдера. | `"example_embeddings_api"` |
| `model_id` | `str` | ID модели или deployment у провайдера. | `"case-embedding"` |
| `model_revision` | `str` | Закреплённая версия весов/deployment. Если API не позволяет её закрепить, ограничение явно фиксируем до допуска профиля. | `"revision-1"` |
| `endpoint` | `str \| None` | Адрес удалённого сервера; для локальной модели — `None`. | `"http://embedding:8080"` |
| `credential_env` | `str \| None` | Имя переменной окружения с секретом; значение читается внутри адаптера и не попадает в DTO/логи. | `"EMBEDDING_API_KEY"` |
| `max_concurrency` | `int` | Положительный предел одновременных вычислений/сетевых вызовов в этом процессе. Общую квоту сервера настраиваем также на стороне сервера. | `2` |
| `embedding_dimensions` | `int \| None` | Положительная размерность только для embedding; для остальных ролей — `None`. | `1024` |

Одинаковый `profile_id` не может означать разные настройки. Для query и document используется один embedding-профиль, но адаптер применяет соответствующие роли инструкции. Размерности недостаточно для совместимости: при смене модели или правил кодирования нужна новая конфигурация индекса и переиндексация. До реализации фиксируем профиль в конфигурации развёртывания; автоматическая смена профиля на работающем корпусе не поддерживается.

## Эмбеддинги {#embedding-result}

| Поле EmbeddingResult | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| `profile_id` | `str` | Профиль реально выполненного кодирования. | `"embedding-v1"` |
| `vectors` | `list[list[float]]` | Один вектор на текст, в исходном порядке; все координаты конечны, размерность соответствует binding. | `[[0.1, -0.2, ...]]` |

## Reranker {#rerank-result}

| Поле RerankResult | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| `profile_id` | `str` | Профиль reranker. | `"reranker-v1"` |
| `scores` | `list[RerankScore]` | По записи на каждый входной кандидат; порядок исходных индексов. | `[{"candidate_index": 0, "score": 2.4}]` |
| `scores[].candidate_index` | `int` | Индекс в переданном `candidates`, от 0; без пропусков и повторов. | `0` |
| `scores[].score` | `float` | Конечная оценка: больше — релевантнее. Не обязана быть вероятностью или лежать в `[0, 1]`. | `2.4` |

Gateway не отсекает кандидатов. Searcher сортирует по убыванию оценки, при равенстве сохраняет исходный порядок, затем применяет свой порог и `top_k`.

## Детектор инъекций {#injection-result}

| Поле InjectionResult | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| `profile_id` | `str` | Профиль детектора, с которым согласованы правила Guardrails. | `"injection-v1"` |
| `label` | `Literal["benign", "injection"] \| None` | Нативный класс модели, приведённый к общему названию. `None`, если есть только score. | `None` |
| `score` | `float \| None` | Конечная оценка, больше — выше риск инъекции. Шкала зависит от профиля и не считается вероятностью. | `0.8` |

Хотя бы одно из `label`/`score` заполнено. Адаптер не придумывает порог для получения класса из score. Guardrails для закреплённого профиля явно выбирает использование нативного класса либо score и порога; при наличии обоих полей правило приоритета фиксируется там же. До настройки правила профиль не готов к рабочему запуску. Непригодный ответ — ошибка контракта, а не `benign`.

## Генерация {#generation}

| DTO / поле | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| `ModelMessage.role` | `Literal["system", "user", "assistant"]` | Роль сообщения. Адаптер сохраняет разделение инструкций и пользовательских данных либо отклоняет неподдерживаемую конфигурацию. | `"system"` |
| `ModelMessage.content` | `str` | Непустой текст сообщения. | `"Отвечай по предоставленным источникам."` |
| `GenerationOptions.max_output_tokens` | `int` | Положительный предел вывода; не включает бюджет входного контекста. | `512` |
| `GenerationOptions.temperature` | `float \| None` | Неотрицательное значение в допустимом диапазоне модели; `None` использует закреплённую настройку профиля. | `0.0` |
| `ModelGenerationResult.profile_id` | `str` | Профиль генерации. | `"generation-v1"` |
| `ModelGenerationResult.text` | `str` | Собранный текст ответа. Может быть пустым при фильтрации; в `completed` непустой. | `"{\"kind\": \"insufficient_evidence\"}"` |
| `ModelGenerationResult.finish_reason` | `Literal["completed", "length", "filtered"]` | Завершённый ответ / исчерпан лимит вывода / фильтрация провайдером. | `"completed"` |
| `ModelGenerationResult.usage` | `TokenUsage \| None` | Статистика провайдера; `None`, если не предоставлена. | `{"input_tokens": 700, "output_tokens": 120}` |
| `TokenUsage.input_tokens` | `int \| None` | Неотрицательное число входных токенов или неизвестно. | `700` |
| `TokenUsage.output_tokens` | `int \| None` | Неотрицательное число выходных токенов или неизвестно. | `120` |

`ModelGenerationResult` — сырой результат вызова модели. Он **не заменяет** бизнес-DTO [`GenerationResult`](../rag-core/contracts.md#исходы-шагов): JSON, метки `S1` и ID чанков проверяет Answer Generator. Неизвестную причину завершения считаем ошибкой адаптера, а `length`/`filtered` не превращаем в полноценный ответ.

## Ошибки {#errors}

Во всех операциях технические ошибки представлены общим `StepError(code, retryable)` из `rag.contracts`. Детали SDK остаются внутри адаптера. Отмена вызывающей корутины пробрасывается как отмена, а не как успешный результат или самостоятельный повтор.

| `code` | `retryable` | Смысл |
| --- | --- | --- |
| `model_invalid_input` | `False` | Неверный ввод, неположительный timeout или неподдерживаемые параметры. |
| `model_not_ready` | `False` | Роль не настроена либо запуск ещё не завершён. В рабочем профиле это ошибка сборки. |
| `model_profile_mismatch` | `False` | Профиль/размерность не совпадают с ожидаемыми. |
| `model_invalid_response` | `False` | Неполные векторы, неконечные числа, неверные индексы или другой нарушенный DTO. |
| `model_configuration_error` | `False` | Неверный адрес, ключ, версия или несовместимая конфигурация. |
| `model_timeout` / `model_overloaded` / `model_unavailable` | `True` | Временная недоступность, исчерпан бюджет ожидания/вызова либо очередь допуска заполнена. |

Известный постоянный отказ API не маркируем временным. Повтор всего вопроса назначает RAG Core, задания — Ingestion Worker. Gateway не запускает скрытые циклы повторов и не переключает провайдера.
