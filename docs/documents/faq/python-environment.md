:::warning Окружение каркаса
Зафиксирован базовый стек для реализации контрактов. Наличие библиотеки не означает, что её адаптер уже реализован. Модельные SDK, парсеры и аппаратные зависимости выберем по кейсу.
:::

Рабочая ветка — **Python 3.12.x**. `app/.python-version` задаёт `3.12`, `requires-python` в `app/pyproject.toml` допускает только `>=3.12,<3.13`. Patch-обновления разрешены; переход на другую minor-версию требует отдельной проверки моделей и зависимостей.

## Базовый набор

| Библиотека | Назначение |
| --- | --- |
| `pydantic` | DTO и проверка данных. |
| `pydantic-settings` | Конфигурация из окружения; единая проверка настроек при запуске. |
| `fastapi`, `uvicorn` | HTTP Gateway и сервер ASGI. Текущий bootstrap ещё использует stdlib health server. |
| `SQLAlchemy[asyncio]`, `asyncpg`, `alembic` | ORM PostgreSQL, async-драйвер и миграции. Не запускаем миграции автоматически в каждом процессе. |
| `aio-pika` | RabbitMQ: async-публикация, подтверждения и потребители. |
| `redis` | Redis с интерфейсом `redis.asyncio`. Отдельный `aioredis` не нужен. |
| `qdrant-client` | `AsyncQdrantClient`; версия 1.20.0 согласована с сервером и используемым BM25 API. |
| `httpx` | Async HTTP: Telegram Bot API и адаптеры модельных API. |

Для Linux-сервера опция `production` добавляет Gunicorn и `uvicorn-worker`. Это устанавливает зависимости, но не меняет команду bootstrap. Telegram SDK, Celery, модельные фреймворки, парсеры, сторонний логгер и pytest пока не добавляем: HTTP покрывает Bot API, очередью управляют существующие роли, JSON-логи и проверки контрактов уже используют стандартную библиотеку.

## Установка

Из папки `app`, внутри окружения Python 3.12:

~~~text
python -m pip install -c requirements.lock -e .
python -m pip check
python -m unittest discover -s tests -v
python -m rag core
~~~

`pyproject.toml` — источник прямых зависимостей и допустимых диапазонов. `requirements.lock` — проверенный набор точных версий базового окружения, включая транзитивные. `requirements.txt` оставлен как совместимая установка этого набора. Docker устанавливает сам проект с ограничениями из lock-файла.

Опцию Linux-сервера устанавливают как `python -m pip install -c requirements.lock ".[production]"`; дополнительные production-пакеты ограничены диапазонами в pyproject, но не входят в базовый lock. Полный набор окружения проверяем на целевой платформе. [Порядок запуска](../infrastructure/startup.md).

## Как добавить библиотеку

1. Добавить прямую зависимость в `pyproject.toml` с обоснованным диапазоном. SDK конкретной модели добавлять после выбора backend, при необходимости отдельной опцией.
2. В чистом Python 3.12 разрешить новый набор зависимостей и обновить `requirements.lock`. Не копировать `pip freeze` из личного окружения с посторонними проектами.
3. Проверить установку, `pip check`, тесты контрактов и сборку целевого образа. При изменении Python синхронно обновить `requires-python`, `.python-version` и `FROM` в Dockerfile.

Контракты и DTO от выбора библиотеки не меняются без отдельной сверки. [Правила Pydantic](./dto.md).
