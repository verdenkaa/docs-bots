# <span className="operation-badge operation-badge--put">PUT</span> `/admin/users/{user_id}`

## Назначение и доступ

Admin управляет допуском. Личность берётся только из доверенного web-входа в Principal. Способ входа пока открыт; пока адаптер не подключён, защищённая ручка возвращает 503 auth_not_configured, а не доверяет user_id/role из тела.

## Что принимает

Content-Type: application/json, user_id: положительный int в пути.

| Поле JSON | Тип / обязательность | Смысл |
| --- | --- | --- |
| enabled | bool, обязательно | Разрешён ли доступ. |
| role | employee/operator/admin, обязательно | Полномочия интерфейса, не документов. |

Пример: `{"enabled":true,"role":"employee"}`.

## Бизнес-логика

Собрать AccessRecord из пути и тела, вызвать set_user_access. Principal не берётся из JSON. Повторное применение того же состояния безопасно. enabled=False закрывает новые вопросы; ранее принятый вопрос и доставка его итога завершаются, активная работа Core не отменяется.

## Что отдаёт

200 OK, application/json, сохранённый AccessRecord.

## Ошибки и повторы

| HTTP | Причина | Действие |
| --- | --- | --- |
| 401 | Нет проверенной личности. | Войти. |
| 403 | Нет текущего admin-допуска. | Нужен администратор. |
| 422 | Неверное тело/ID. | Исправить. |
| 503 | Вход не настроен / неизвестный коммит. | Повторить то же состояние после восстановления. |
