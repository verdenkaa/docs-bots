## Запуск

Именованный том `worker_spool` подключён к `worker`. Здесь хранятся **результат конвертации**, манифест и подготовленные поисковые наборы. Исходные документы и файлы изображений в этот том не записываются.

## Запись временного файла

Внутренний ключ `uploads/<revision_id>` определяет каталог:

| Файл | Содержимое |
| --- | --- |
| `converted.md` | UTF-8 Markdown с описаниями и плейсхолдерами изображений. |
| `manifest.json` | Название исходника и список ImageRef, без байтов/секретов. |
| `prepared.json` | Неизменяемый PreparedRevision: чанки, примеры, векторы и профили. Появляется до первой записи Qdrant. |

~~~json
{
  "source": {"filename": "Руководство.docx"},
  "images": [
    {"image_id": "e1246aa5-3bba-4a74-8445-60b6271c0551", "description": "Схема согласования"}
  ]
}
~~~

Адаптер сначала пишет во внутренние временные файлы, обеспечивает устойчивость и атомарную видимость полного Markdown/манифеста, затем возвращает ключ. После аналогичной записи prepared.json разрешается начинать запись индексов. Повреждённый существующий подготовленный набор — ошибка, не основание незаметно сгенерировать другой.

## Приём и восстановление

1. Gateway сохраняет изображения S3 и результат конвертации, затем транзакцией PostgreSQL регистрирует редакцию/outbox. Только после коммита возвращает accepted.
2. Worker читает Markdown. Если prepared.json уже есть, использует его **вместо** повторного разбиения, генерации примеров и embedding. Если его ещё нет, подготовка может выполняться заново: запись Qdrant ещё не разрешалась.
3. После публикации/окончательного сбоя без незавершённой записи Worker удаляет весь каталог и очищает staging_ref. Для qdrant_write_pending=true каталог сохраняется до сверки.
4. До возобновления приёма загрузок выбирает старые остатки, включая неполные записи. Удаляет только после is_staging_referenced=False, дождавшись возможного коммита регистрации. При недоступном PostgreSQL ничего не удаляет.
5. Потеря тома до публикации — технический сбой задания, нужна новая загрузка оригинала. После штатной публикации том больше не нужен для поиска.

Долговременные данные: чанки/примеры в Qdrant, изображения S3, состояние и source_name/image_ids в PostgreSQL. Уборка каталога не затрагивает S3 и метаданные источника. [PostgreSQL](../postgresql/index.md)
