# RAG Container Manager

Откройте `manage.bat` на Windows или запустите `sh manage.sh` на Linux/macOS. Менеджер использует `.env` рядом со скриптом и создаёт его только на новом стенде, если файла ещё нет. Для сервера подготовьте отдельный `.env` со своими секретами до первого запуска. В меню выберите `1`, чтобы поднять инфраструктуру.

Введите номер и нажмите Enter. Таблица обновляется в том же окне. Клавиша `D` открывает детали ошибки, пункт `9` — логи выбранного сервиса, `M` — возврат из журнала.

Меню публикует порты инфраструктуры на loopback. Для прямой команды используйте `--local up infra`, для меню на сервере — `--no-local`. Пункты `2` (`up app`) и `3` (`up full`) автоматически собирают недостающие образы каркаса из `app/Dockerfile`. Если в `.env` указан свой `CORE_IMAGE` или `WORKER_IMAGE`, менеджер использует этот образ для соответствующей роли. После изменения кода каркаса выберите пункт `11` (`Update app images`). Параметр `--help` показывает команды.

Чтобы показать адрес нового сервиса в таблице, добавьте в `ENDPOINTS` в `manager.py` его внутренний TCP-порт и при наличии путь веб-интерфейса. Опубликованный порт менеджер считывает из запущенного контейнера.

## S3-хранилище

Во все сценарии `up infra`, `up app` и `up full` входит сервис `s3` на [RustFS 1.0.5](https://github.com/rustfs/rustfs/releases/tag/1.0.5). Он хранит объекты в именованном томе `s3_data`, перезапускается вместе со стендом и проходит проверку готовности S3 API и консоли. `stop` сохраняет данные.

Локально запустите `manage.bat --local up infra` или `sh manage.sh --local up infra`. S3 API доступен на `http://127.0.0.1:9000`, консоль — на `http://127.0.0.1:9001`. Порты меняются через `S3_PORT` и `S3_CONSOLE_PORT` в `.env`. В консоли можно создать приватный bucket для документов.

Логин консоли и S3 access key задаёт `S3_ACCESS_KEY` (по умолчанию `rag`), пароль / secret key — `S3_SECRET_KEY`. На новом стенде менеджер генерирует секрет. В существующий `.env` при первом `up` он добавляет только отсутствующий `S3_SECRET_KEY`, сохраняя остальные настройки. Явно заданное, в том числе пустое, значение не заменяется; при ручной настройке заполните его. Если том S3 уже существует, а секрет утрачен, восстановите прежний секрет. Пункт `13` показывает настроенный `S3_SECRET_KEY` вместе с остальными паролями.

На сервере используйте `sh manage.sh --no-local up app` (для одной инфраструктуры — `up infra`). S3 работает в сети Compose по адресу `http://s3:9000`; его порты на хост не публикуются. `core` и `worker` получают `S3_ENDPOINT_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `S3_REGION=us-east-1` и запускаются после готовности хранилища. Для уже созданных контейнеров приложения примените новые переменные через `update local` (каркас) или `update registry` (образы релиза). SDK настраивайте на path-style адресацию. Реализация S3-адаптера приложения остаётся отдельной задачей.

Для доступа к консоли сервера можно временно запустить стенд с `--local`, что опубликует порты инфраструктуры только на loopback сервера, и открыть SSH-туннель:

```bash
ssh -N -L 9000:127.0.0.1:9000 -L 9001:127.0.0.1:9001 user@SERVER
```

Чтобы после этого убрать опубликованные порты S3, пересоздайте только `s3` с базовым `compose.yaml` и прежним `.env`: `docker compose -p rag-hackathon -f compose.yaml up -d --no-deps --force-recreate s3`. Выполните команду из `container-manager/`; том сохранится.

Один экземпляр с одним томом рассчитан на текущий односерверный стенд. Для резервного копирования сохраняйте `s3_data` вместе с остальными постоянными данными; этот режим не даёт репликации между серверами. [Запуск RustFS в Docker](https://docs.rustfs.com/en/installation/container/docker).

Проверки менеджера без запущенного движка: `python -m unittest discover -s container-manager/tests -v` из корня репозитория. При наличии Docker CLI тесты также проверяют итоговую конфигурацию Compose в локальном и серверном режимах.
