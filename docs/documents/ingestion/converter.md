Профиль проверен на трёх PDF кейса, их DOCX-копиях (пересобраны из PDF) и трёх небольших DOCX с подставными OCR/VLM: recognize_text и describe_image в Model Gateway пока заглушки, поэтому документ с картинками до их реализации не конвертируется. **[Контракт convert_document](./entrypoints.md#convert-document)** · [DTO](./contracts.md#dto)

Конвертер — подмодуль Gateway, не отдельный сервис. Возвращает UTF-8 Markdown и изображения для записи Gateway в S3.

## Порядок

1. Проверить содержимое и выбрать разрешённый обработчик. Неизвестный формат явно отклонить: расширяемая система не обещает поддержку всех файлов.
2. Сохранить порядок текста, заголовков, таблиц, значимые URL/операторы. Не переписывать весь текст моделью.
3. Извлечь изображения: OCR через recognize_text и описание схемы/интерфейса через describe_image в Model Gateway.
4. Назначить `uuid5(revision_id, "image:" + str(image_no))`, номера с 0 в порядке извлечения.
5. Поставить `![Описание](image://<uuid>)`; вернуть Markdown и байты/MIME/ImageRef изображений. Сам конвертер S3 не пишет.
6. Проверить совпадение наборов ID в Markdown и images. Описание экранировать по Markdown. Пустой результат не принимать.

Готовый Markdown проходит ту же проверку. Произвольный URL/путь картинки не является нашим image_id: разрешённый обработчик должен получить файл безопасным способом либо отказать. Нельзя скачивать произвольные URL или читать локальные файлы по ссылкам в документе.

## Исполнение

Оригинал находится только в ограниченном потоке/буфере вызова, на диск не записывается. Обработчик, которому требуется дисковый оригинал, не включаем без изменения этого решения. CPU-разбор работает вне event loop в управляемом процессе. Gateway ограничивает общий срок и останавливает зависшего исполнителя с потомками; одной отмены корутины недостаточно. Модельные вызовы имеют бюджеты внутри общего срока.

## Реализованный профиль

Формат определяется по содержимому, а не по расширению. Обработчики реализуют один интерфейс `DocumentParser.parse(data, add_image) -> str` в `rag/ingestion/_parsers.py`; новый формат — это ещё одна реализация и строка в `PARSERS`.

| Вход | Как распознаём | Обработчик |
| --- | --- | --- |
| PDF | Сигнатура `%PDF-`. | Есть теги структуры (экспорт Word/Confluence) — читаем теги через pdfplumber и pypdf, без моделей. Тегов нет или они формальные — docling без OCR. Нет читаемого текстового слоя (скан) — unsupported_format. |
| DOCX | ZIP с `word/document.xml`. | Собственная разметка Word читается напрямую (`rag/ingestion/_docx.py`), без моделей и без docling: заголовки и списки — по стилям и нумерации, таблицы, внешние ссылки, встроенные картинки. Оглавление, колонтитулы, сноски и удалённый в режиме правки текст не переносятся. Таблица из одной колонки выводится цитатой, как рамка в PDF. |
| Markdown | Расширение `.md`/`.markdown`, UTF-8 без нулевых байтов. | Пропускается как есть, без процесса разбора и без вызовов моделей. Ссылки на картинки остаются обычным текстом: файлы и URL не читаются. Текст с `image://` отклоняется как conversion_failed. |
| Остальное | — | unsupported_format. PPTX, XLSX и HTML не проверялись и не включены. |

docling — необязательная зависимость (`pip install .[docling]`): тянет torch и не ставится на Alpine. Без неё PDF без тегов получает unsupported_format; DOCX, PDF с тегами и Markdown от неё не зависят.

Ограничения DOCX — **предположения, не решения команды**: номера автонумерации заголовков не восстанавливаются; буквенная и римская нумерация списков выводится цифрами; картинки EMF/WMF и картинки по внешним ссылкам пропускаются; DOCX с DTD или с частью архива больше 256 MiB после распаковки — conversion_failed.

PDF и DOCX разбирает одноразовый процесс `python -m rag.ingestion._convert_worker` в своей группе процессов: оригинал приходит в stdin, Markdown и PNG-картинки возвращаются в stdout, диск не используется. Процесс получает лимит адресного пространства и не получает секреты окружения. По сроку или отмене вся группа останавливается через SIGKILL.

Описание картинки — ответ describe_image; непустой текст recognize_text добавляется как «Текст на изображении: …». Одинаковые картинки одного документа (значки кнопок) описываются один раз, но каждая получает свой image_id. Номера изображений идут в порядке появления в Markdown. Описание длиннее лимита обрезается с «…», чтобы неделимый плейсхолдер не превысил бюджет чанка — **предположение, не решение команды**.

Исходы сверх перечисленных в контракте — **предположения до согласования с Gateway**: пустой вход даёт StepError(invalid_upload, False); срок разбора, общий срок, падение исполнителя и нехватка памяти — StepError(converter_unavailable, True).

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| RAG_CONVERTER_MAX_UPLOAD_BYTES | 50 MiB | Размер оригинала; больше — too_large. |
| RAG_CONVERTER_MAX_IMAGES / RAG_CONVERTER_MAX_IMAGE_BYTES | 500 / 20 MiB | Число и размер картинок; больше — too_large. |
| RAG_CONVERTER_MAX_DESCRIPTION_CHARS | 2000 | Длина описания одной картинки. |
| RAG_CONVERTER_TOTAL_TIMEOUT_S | 1800 | Весь convert_document вместе с OCR/VLM. |
| RAG_CONVERTER_PARSE_TIMEOUT_S / RAG_CONVERTER_PARSE_MEMORY_BYTES | 300 / 4 GiB | Срок и память процесса разбора. |
| RAG_CONVERTER_DESCRIBE_TIMEOUT_S / RAG_CONVERTER_OCR_TIMEOUT_S | 60 / 30 | Бюджет одного вызова Model Gateway. |
| RAG_CONVERTER_MODEL_CONCURRENCY | 4 | Сколько картинок описывается одновременно. |

[MarkItDown](https://github.com/microsoft/markitdown) — ранее предложенный кандидат для текстовой части; у него есть потоковый convert_stream, но это само по себе не гарантирует все нужные свойства каждого обработчика. Допуск конкретного обработчика зависит от тестов таблиц, изображений, памяти и отсутствия записи оригинала. Установленная библиотека сама по себе не подтверждает эти свойства.

## Проверка профиля

| Вход | Ожидание |
| --- | --- |
| Заголовки и таблицы | Читаемый Markdown без потери значимых значений. |
| Скриншот/схема | OCR/описание, байты изображения и совпадающий плейсхолдер. |
| Картинка без текста | Пустой OCR допустим; VLM может дать содержательное описание. |
| Повреждение/неизвестный тип | Отказ, а не частично принятая редакция. |
| Зависание/превышение памяти | Управляемая остановка без accepted. |

Форматы, модели и лимиты — конфигурация испытанного профиля. До его проверки готовность приёма не объявляем.
