## Граница

В контейнере `worker` работают Gateway и последовательный Worker. [HTTP-адаптер](./http-upload.md) принимает PDF/DOCX через `POST /admin/ingestion/upload` с Bearer-токеном из env/.env и передаёт поток в Python-вход Gateway. Gateway вызывает свой конвертер, сохраняет изображения в S3 и готовый Markdown во временном томе. Gateway также формирует и сохраняет полный массив чанков DocumentBatch до регистрации задания. После коммита задания и outbox загрузка принята. Worker получает `job_id`, читает готовую партию и индексирует её без повторного разбиения. Оригиналы не сохраняем. Конвертер и разбиение реализованы; техническая недоступность хранилищ или моделей даёт HTTP 503.

Операции Runtime для DocumentBatch и резервирования версий реализованы по согласованным контрактам. Перед запуском применяют миграции до актуального head Alembic, настраивают профили моделей, запускают Relay, recovery и потребителя ingestion.jobs. Pending-записи с неизвестным исходом Qdrant требуют операторской сверки.

~~~mermaid
flowchart LR
 A["Адаптер с проверкой доступа"] --> G["Gateway / Converter"]
 G -->|"изображения"| S3[("S3")]
 G -->|"Markdown + манифест"| V[("worker_spool")]
 G -->|"редакция + outbox"| P[("PostgreSQL")]
 P --> R["Queue Relay в core"] --> MQ[("RabbitMQ · ingestion.jobs")]
 MQ --> W["Worker"]
 V --> W
 W -->|"чанки + примеры темы"| Q[("Qdrant")]
 W -->|"публикация обоих наборов"| P
~~~

Модели вызываются через Model Gateway, хранилища — через Runtime. Документ не отправляется в сценарий ответа RAG Core.

## Новый документ или новая редакция

| Идентификатор | Что обозначает |
| --- | --- |
| `document_id` | Стабильный документ. При входе None регистрация находит или создаёт его по точному уникальному filename; явный ID проверяется на соответствие имени. |
| `revision_id = job_id` | Одна загрузка и задание; повтор Worker не меняет ID. |
| `chunk_id` | UUIDv5 редакции и номера чанка с 0. |
| ID примера темы | UUIDv5 редакции и строки `question:<номер>` с 0. |
| `image_id` | UUID изображения S3, назначенный Gateway. |
| Поколение корпуса | Версия всего опубликованного набора редакций. |

Имя файла теперь служит точным уникальным ключом поиска документа и подписью источника. Сравнение регистрозависимое, без скрытой нормализации; переименование является новым документом. Постоянной идентичностью после поиска остаётся document_id. Worker читает опубликованную версию по имени и атомарно резервирует следующую за job_id: первая — 0, далее base_version + 1. Порядок регистрации revision_no и поколение корпуса — отдельные значения.

## Публикация

Worker сохраняет подготовленные чанки и примеры вопросов, записывает оба набора Qdrant, проверяет полноту и лишь затем публикует редакцию транзакцией PostgreSQL. Ошибка оставляет прежнюю редакцию видимой.

### Пример замены редакции

| Момент | Qdrant | Что читают вопросы |
| --- | --- | --- |
| Поколение 41 | Чанки и примеры R1. | R1. |
| Подготовка R2 | R1 и невидимые точки R2. | Всё ещё R1. |
| Коммит поколения 42 | Обе редакции до уборки. | Новые вопросы — R2; закрепившие 41 — R1. |

После завершения убираем Markdown/манифест/подготовленные наборы. Уборка старых точек не удаляет изображения, готовые ответы и метаданные HTML-заглушки. [Владение](../architecture/data-and-versions.md) · [Worker](./worker.md)

## Партия и метаданные

DocumentBatch содержит source с единым filename/access_level и непустой упорядоченный chunks. PreparedChunk хранит текст с плейсхолдерами image://UUID, локатор и ImageRef. Номер публикуемой версии не берётся из входных чанков: его назначает PostgreSQL. Access_level — обязательная непрозрачная метка из доверенного адаптера; словарь уровней и фильтрация закрытых документов требуют отдельного согласования с поиском. Текущий общий корпус использует employees. Одна метка в payload сама по себе не реализует разграничение доступа.
