## Маршруты RabbitMQ

| Очередь | Кто ставит работу в очередь | Кто забирает | Что лежит в сообщении |
| --- | --- | --- | --- |
| `rag.questions` | RAG API | RAG Core | Ссылка на сохранённый запрос. |
| `rag.results` | RAG Core | RAG API | Ссылка на запрос, по которому уже сохранён итог для доставки. |
| `ingestion.jobs` | Ingestion Gateway | Ingestion Worker | Ссылка на зарегистрированное задание. |

RAG API и RAG Core передают работу друг другу через RabbitMQ. Текст вопроса, готовый итог, данные для доставки и этапы работы храним в PostgreSQL. В RabbitMQ передаём идентификатор и назначение работы, а получатель загружает нужные данные через Runtime. Входной файл хранится в рабочем томе до завершения индексации. Outbox хранит намерение отправить уведомление и маршрут. **[Queue Relay](../infrastructure/queue-relay.md)** публикует его в RabbitMQ от имени владельца этапа.

~~~mermaid
sequenceDiagram
  participant A as RAG API
  participant P as PostgreSQL
  participant L as Queue Relay
  participant Q as RabbitMQ
  participant C as RAG Core
  A->>P: Сохранить вопрос и outbox одной транзакцией
  L->>P: Взять запись outbox для rag.questions
  L->>Q: Опубликовать уведомление с идентификатором
  Q->>C: Передать уведомление из rag.questions
  C->>P: Прочитать вопрос и состояние
  C->>P: Сохранить итог и outbox для rag.results
  C-->>Q: Подтвердить обработку
  L->>P: Взять запись outbox для rag.results
  L->>Q: Опубликовать уведомление о готовом итоге
  Q->>A: Передать уведомление из rag.results
  A->>P: Прочитать итог для доставки
~~~

## Когда работа считается принятой

1. **Приём.** RAG API через Runtime сохраняет вход и запись outbox для `rag.questions` одной транзакцией. Ingestion Gateway сначала сохраняет временный файл, затем одной транзакцией регистрирует редакцию с заданием и запись outbox. После фиксации этой транзакции шлюз может подтвердить приём.
2. **Публикация.** Queue Relay берёт запись outbox и отправляет её в RabbitMQ. Запись считается отправленной после подтверждения публикации и проверки маршрута в очередь. Сбой до обновления outbox может привести к повтору с тем же идентификатором сообщения.
3. **Обработка.** Получатель проверяет сохранённое состояние по идентификатору запроса или задания и этапу. Подтверждает сообщение после фиксации результата или долговременного состояния для повтора. Если нужен следующий маршрут, получатель сохраняет его запись outbox вместе с переходом. Так RAG Core передаёт готовый результат в `rag.results`.

## Порядок и повторы

- RAG Core обрабатывает ограниченное число вопросов одновременно. Лимит выдачи RabbitMQ учитывает доступную ёмкость обработчика. [Подтверждения и prefetch RabbitMQ](https://www.rabbitmq.com/docs/confirms)
- Core берёт следующий вопрос каждого чата по сохранённому порядку приёма. RAG API по тому же порядку доставляет результаты и учитывает лимиты Telegram. Если более позднее уведомление пришло первым, владелец сохраняет ожидание и подтверждает уведомление. Завершая предыдущий этап, владелец ставит ожидающий следующий элемент в outbox. Эти переходы согласуем в PostgreSQL, чтобы при одновременном завершении и постановке на ожидание следующий элемент получил уведомление.
- Ingestion Worker выполняет задания последовательно. Новая редакция становится видимой после готовности индекса и коммита в PostgreSQL. До публикации повтор использует тот же временный файл и те же ID точек. После публикации возобновляется только незавершённая уборка. [Порядок работы Ingestion Worker](../ingestion/worker.md)
- RAG API при повторе доставки использует сохранённый результат. Если Telegram принял сообщение, но ответ на отправку потерялся, повтор может дать дубликат. Число попыток ограничено. Если Telegram вернул `retry_after`, время новой попытки учитывает эту задержку. [Правила доставки](../telegram/index.md) · [Telegram Bot API](https://core.telegram.org/bots/api#responseparameters)

Внутренние шаги поиска и генерации выполняются вызовами Python внутри RAG Core. RabbitMQ соединяет приём, фоновую работу и доставку. [Сборка конвейеров](./module-composition.md) · [Состояния и сбои](./lifecycle.md)
