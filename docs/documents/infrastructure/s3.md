S3 хранит извлечённые изображения документов. Контракты адаптера находятся в `rag.runtime.s3`: Ingestion Gateway вызывает `put_image`, RAG API — `get_image`. Оригиналы документов здесь не сохраняются. Реализация клиента пока остаётся заглушкой каркаса.

`ImageContent` (поля `data: bytes`, `mime_type: NonEmptyText`) определён в [общих DTO](../rag-core/contracts.md#общие-dto). Байты живут в памяти текущего вызова и не попадают в очередь, кеш или логи.

## Путь изображения

Gateway → `put_image(image_id, image)` → S3. Готовый ответ, включая кешированный, содержит плейсхолдер `image://UUID` и соответствующий `ImageRef`. RAG API строит `ImagePart`, вызывает `get_image(image_id)` и отправляет файл через Telegram `sendPhoto`. Для этого не нужны повторный поиск или генерация ответа. [Доставка](../telegram/module/entrypoints.md#send-answer)

## <span className="operation-badge operation-badge--async">ASYNC</span> `get_image` {#get-image}

~~~python
async def get_image(image_id: UUID) -> ImageContent: ...
~~~

**Кто вызывает.** send_answer для ImagePart.

### Что принимает

| Параметр | Тип | Зачем нужен | Пример |
| --- | --- | --- | --- |
| image_id | UUID | Разрешённый ID сохранённого ответа. | UUID(...) |

### Что отдаёт

**Формат.** ImageContent.

| Поле / значение | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| data / mime_type | bytes / str | Изображение из S3 по детерминированному ключу. | b"…" / "image/png" |

### Правила и ошибки

Только настроенный bucket/ключ image_id, без URL от модели. Не найдено — постоянный StepError; временная сеть — retryable. Получение не требует исходного документа или запроса к Qdrant.

## <span className="operation-badge operation-badge--async">ASYNC</span> `put_image` {#put-image}

~~~python
async def put_image(image_id: UUID, image: ImageContent) -> None: ...
~~~

**Кто вызывает.** Ingestion Gateway после извлечения изображения и до подтверждения загрузки.

### Что принимает

| Параметр | Тип | Зачем нужен | Пример |
| --- | --- | --- | --- |
| image_id | UUID | ID, который Gateway помещает в плейсхолдер и ImageRef. | UUID(...) |
| image | ImageContent | Байты и MIME извлечённого изображения. | ImageContent(...) |

### Что отдаёт

**Формат.** None.

| Поле / значение | Тип | Смысл | Пример |
| --- | --- | --- | --- |
| return | None | Объект подтверждённо записан/уже совпадает по содержимому. | None |

### Правила и ошибки

Стабильный ID не перезаписывается другим содержимым. Совпадающий повтор безопасен; конфликт — постоянный StepError. Неизвестный исход требует проверки существующего объекта. Оригинальный документ не сохраняется этим вызовом.

## Хранение и доступ

Bucket, endpoint, ключи и лимиты задаёт Runtime. image_id однозначно задаёт объект; MIME проверяется по содержимому. S3-учётные данные не помещаются в DTO, Markdown, кеш или логи. RAG API получает файл через get_image и отправляет его в Telegram, пользователю не требуется публичный S3-bucket.

Удаление чанков, временного Markdown или истечение Redis TTL не разрешают удалять изображение: на него могут ссылаться готовые доставки/ответы/история. До утверждения политики хранения автоматическое удаление S3 отключено; это относится и к остаткам неудачного приёма. Политику и процедуру очистки фиксируем отдельно, не переиспользуя image_id для другого файла. Архива оригиналов нет: утрата картинки требует восстановления S3 либо новой загрузки документа.
