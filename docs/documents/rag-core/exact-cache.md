## Чтение и запись

Exact Cache вызывает `read_cached_answer(query)` и сравнивает поколение из поля `value` DTO `CacheRead` с переданным Core. При совпадении возвращает `answer_text`, `sources` и `images`. Для старого значения вызывает `delete_cached_answer_if_unchanged(query, compare_token)`, для более нового возвращает промах. При записи передаёт `CachedAnswer` в `write_cached_answer_if_not_older`. Чтение, удаление и запись ограничиваем по времени. Сбой кеша не задерживает основной путь сверх этого бюджета. [Функции Redis](../infrastructure/redis/contracts.md)

Core сохраняет в кеш только новый ответ с источниками после успешного коммита. При попадании в кеш Core сохраняет готовый итог для своего запроса и сразу переходит к доставке. Для теста или запуска без кеша достаточно подставить `get_answer` с постоянным промахом и `store_answer` без записи. [DTO результата](./contracts.md#общие-dto) · [Формат записи и правила Redis](../infrastructure/redis/index.md)

При несовместимом изменении моделей или правил обработки применяется [инвалидация при обновлении](../faq/production-update.md#изменение-моделей-и-правил-ответа): проверка поколения корпуса сама по себе не обнаруживает смену профиля приложения.

Кеш хранит готовый Markdown ответа, а не исходные Markdown документов. Картинки представлены только ID/описаниями; S3 получает RAG API. Кеш не обходит topic gate: Guardrails уже сравнил вопрос с примерами нужных редакций. Низкое сходство ведёт в Support до чтения кеша.
