## Запуск

Подключаем именованный рабочий том `worker_spool` к `worker`. Ingestion Gateway пишет входной файл, Ingestion Worker читает его для подготовки редакции и возможного повтора. Файл временный по сроку хранения, а том сохраняет его при рестарте до завершения задания.

## Запись временного файла

В PostgreSQL у редакции хранится временная ссылка. Например:

```json
{
  "revision_id": "bb32ecbf-082b-4497-a41f-4b61aa56a139",
  "staging_ref": "uploads/bb32ecbf-082b-4497-a41f-4b61aa56a139"
}
```

`staging_ref` — внутренний ключ загрузки, который генерирует приложение. В каталоге загрузки лежат файл `source` и `manifest.json` с `filename` и `source_url`. Адаптер делает файл и манифест доступными как одну загрузку и только после этого возвращает ключ. Ссылки в ответе строим по доступному адресу источника или локатору из Qdrant.

Пример `manifest.json`.

~~~json
{ "filename": "Руководство по установке.pdf", "source_url": null }
~~~

## Приём и восстановление

1. Ingestion Gateway завершает устойчивую запись файла в том, затем регистрирует редакцию с заданием и outbox одной транзакцией PostgreSQL. После коммита можно подтвердить приём.
2. Ingestion Worker читает файл по `staging_ref`. При повторе индексации использует тот же файл. Если рабочий том потерян и подготовку продолжить невозможно, задание завершается техническим сбоем и документ нужно загрузить заново.
3. После публикации либо окончательного завершения с ошибкой worker удаляет файл и очищает `staging_ref`. При рестарте он повторяет незавершённую уборку. Отсутствующий файл на этом этапе считаем уже убранным.
4. До возобновления приёма загрузок проверяем старые кандидаты. Включаем и прерванные записи, для которых файл или манифест записаны лишь частично. Удаляем загрузку, только если `is_staging_referenced` вернул `False` после завершения возможной транзакции регистрации. При недоступном PostgreSQL оставляем её до следующей проверки.
