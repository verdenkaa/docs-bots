Конвертер — подмодуль Gateway, не отдельный сервис. Возвращает UTF-8 Markdown и изображения для записи Gateway в S3.

## Порядок

1. Проверить содержимое и выбрать разрешённый обработчик. Неизвестный формат явно отклонить: расширяемая система не обещает поддержку всех файлов.
2. Сохранить порядок текста, заголовков, таблиц, значимые URL/операторы. Не переписывать весь текст моделью.
3. Извлечь изображения: OCR через recognize_text и описание схемы/интерфейса через describe_image в Model Gateway.
4. Назначить `uuid5(revision_id, "image:" + str(image_no))`, номера с 0 в порядке извлечения.
5. Поставить `![Описание](image://<uuid>)`; вернуть Markdown и байты/MIME/ImageRef изображений. Сам конвертер S3 не пишет.
6. Проверить совпадение наборов ID в Markdown и images. Описание экранировать по Markdown. Пустой результат не принимать.

Готовый Markdown проходит ту же проверку. Произвольный URL/путь картинки не является нашим image_id: разрешённый обработчик должен получить файл безопасным способом либо отказать. Нельзя скачивать произвольные URL или читать локальные файлы по ссылкам в документе.

## Исполнение

Оригинал находится только в ограниченном потоке/буфере вызова, на диск не записывается. Обработчик, которому требуется дисковый оригинал, не включаем без изменения этого решения. CPU-разбор работает вне event loop в управляемом процессе. Gateway ограничивает общий срок и останавливает зависшего исполнителя с потомками; одной отмены корутины недостаточно. Модельные вызовы имеют бюджеты внутри общего срока.

## Реализованный профиль

Формат определяется по содержимому, а не по расширению. Обработчики реализуют один интерфейс `DocumentParser.parse(data, add_image) -> str` в `rag/ingestion/_parsers.py`; новый формат — это ещё одна реализация и строка в `PARSERS`.

| Вход | Как распознаём | Обработчик |
| --- | --- | --- |
| PDF | Сигнатура `%PDF-`. | Разбираем через pdfplumber и pypdf независимо от наличия и процента покрытия тегами. При наличии тегов сохраняем их заголовки, списки и таблицы; не охваченный деревом текст добавляем по координатам строк. Каждое видимое вхождение встроенного изображения извлекаем независимо от Figure и передаём в OCR/VLM как иллюстрацию. Страница с растровыми изображениями без извлекаемого текста даёт unsupported_format. |
| DOCX | ZIP с `word/document.xml`. | Собственная разметка Word читается напрямую (`rag/ingestion/_docx.py`), без переписывания текста моделью и без docling: заголовки и списки — по стилям и нумерации, таблицы, внешние ссылки, встроенные картинки. Колонтитулы включаются один раз, сноски и концевые сноски — в скобках сразу после места ссылки. Учитывается актуальный текст правок; оглавление не переносится. Таблица из одной колонки выводится цитатой, как рамка в PDF. |
| Markdown | Расширение `.md`/`.markdown`, UTF-8 без нулевых байтов. | Разбирается в ограниченном процессе, без вызовов моделей; текст не переписывается. Ссылки на картинки остаются обычным текстом: файлы и URL не читаются. Текст с `image://` отклоняется как conversion_failed. |
| Остальное | — | unsupported_format. PPTX, XLSX и HTML не проверялись и не включены. |

Необязательная зависимость docling не используется активными обработчиками. PDF без тегов обрабатывается тем же встроенным парсером.

Теги PDF помогают восстановить структуру Markdown, но не служат условием допуска. Порог покрытия 95% и проверка наличия заголовков в длинном документе не применяются. При отсутствующей или нечитаемой структуре текст собирается постранично; точное восстановление структуры таблиц и порядка колонок без тегов не гарантируется. Повреждённый или недоступный без пароля PDF по-прежнему может завершиться ошибкой конвертации; лимиты размера, памяти и времени сохраняются.

Сканы пока не принимаются. Если на странице есть растровые изображения и нет непустого извлекаемого текста вне Artifact, весь PDF получает `StepError(unsupported_format, False)` до извлечения изображений и вызовов OCR/VLM. Это относится и к смешанному PDF с текстовыми и сканированными страницами; пустые страницы без изображений допустимы. Правило также исключает страницы, состоящие только из иллюстраций. Анализ содержимого картинки для определения скана не выполняется: при наличии текстового слоя изображение считается иллюстрацией.

Учитываются нарисованные в документе вхождения изображений, включая inline-изображения и изображения внутри Form XObject. Неиспользуемый объект в ресурсах страницы не создаёт плейсхолдер. Каждое вхождение получает свой image_id; при невозможности извлечь исходную картинку отрисовываем её область страницы. Изображения внутри пропускаемых тегов оглавления или Artifact также обрабатываются в PDF, прошедшем проверку текстового слоя.

В DOCX колонтитулы читаются по ссылкам секций: явно заданные варианты верхнего колонтитула идут перед текстом секции, нижнего — после него. Одна и та же часть архива включается один раз за документ, без повторения на каждой странице. Неиспользуемые части колонтитулов не читаются. Сноски и концевые сноски подставляются в месте ссылки: `за пять дней (учитываются только рабочие дни)`. Несколько абзацев сноски разделяются `; `. Таблицы, ссылки и картинки внутри этих частей обрабатываются тем же конвертером; относительные пути разрешаются через собственный файл relationships каждой части. Добавленный и перемещённый в новое место текст сохраняется; удалённый текст, прежние места перемещений, удалённые строки и ячейки таблиц исключаются. История правок не выводится.

Встроенные EMF/WMF отрисовываются Inkscape в PNG и проходят общий OCR/VLM с плейсхолдером. Поддерживаются также WMF без placeable-заголовка. Повторное использование одного метафайла не запускает отрисовку заново, но каждое вхождение получает свой маркер. Linux-образ приложения включает Inkscape и DejaVu; при локальном запуске их нужно установить системным пакетным менеджером. Без Inkscape или Linux memfd метафайл даёт техническую ошибку `ingestion_configuration_error`. Повреждённый метафайл даёт `conversion_failed`. Внешняя картинка по-прежнему не скачивается и вызывает `unsupported_format` для всего DOCX, включая ссылки из колонтитулов и сносок.

Параметры отрисовки EMF/WMF — **предположение профиля**: 144 dpi, максимум 4096 пикселей по длинной стороне с сохранением пропорций и белым фоном. Остальные ограничения DOCX — **предположения, не решения команды**: номера автонумерации заголовков не восстанавливаются; буквенная и римская нумерация списков выводится цифрами; DOCX с DTD или с частью архива больше 256 MiB после распаковки — conversion_failed.

PDF, DOCX и Markdown разбирает одноразовый процесс `python -m rag.ingestion._convert_worker` в своей группе процессов: оригинал приходит в stdin, Markdown и PNG-картинки возвращаются в stdout. Оригинал и извлечённые изображения на диск не записываются. Inkscape читает метафайл через Linux memfd; временный каталог содержит только ссылку на дескриптор в памяти и служебный профиль/кеш рендерера, после обработки он удаляется. Процесс получает лимит адресного пространства и не получает секреты окружения. По сроку или отмене вся группа, включая Inkscape, останавливается через SIGKILL.

Описание картинки — ответ describe_image; непустой текст recognize_text добавляется как «Текст на изображении: …». Одинаковые картинки одного документа (значки кнопок) описываются один раз, но каждое извлечённое вхождение получает свой image_id; повторная ссылка на одно извлечённое изображение сохраняет его ID. Номера изображений идут в порядке появления в Markdown. Описание длиннее RAG_CONVERTER_MAX_DESCRIPTION_CHARS обрезается с «…» — **предположение, не решение команды**. Разбиение учитывает весь плейсхолдер, включая описание и UUID; лимит описания и бюджет чанка независимы. Слишком большой неделимый плейсхолдер даёт chunk_too_large по существующему контракту prepare_chunks.

Исходы сверх перечисленных в контракте — **предположения до согласования с Gateway**: пустой вход даёт StepError(invalid_upload, False); срок разбора, общий срок, падение исполнителя и нехватка памяти — StepError(converter_unavailable, True).

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| RAG_CONVERTER_MAX_UPLOAD_BYTES | 50 MiB | Размер оригинала; больше — too_large. |
| RAG_CONVERTER_MAX_MARKDOWN_BYTES / RAG_CONVERTER_MAX_PARSER_OUTPUT_BYTES | 20 / 128 MiB | Размер готового Markdown и полного ответа процесса. |
| RAG_CONVERTER_MAX_IMAGES / RAG_CONVERTER_MAX_IMAGE_BYTES | 500 / 20 MiB | Число и размер картинок; больше — too_large. |
| RAG_CONVERTER_MAX_DESCRIPTION_CHARS | 2000 | Длина описания одной картинки. |
| RAG_CONVERTER_TOTAL_TIMEOUT_S | 1800 | Весь convert_document вместе с OCR/VLM. |
| RAG_CONVERTER_PARSE_TIMEOUT_S / RAG_CONVERTER_PARSE_MEMORY_BYTES | 300 / 4 GiB | Срок и память процесса разбора. |
| RAG_CONVERTER_DESCRIBE_TIMEOUT_S / RAG_CONVERTER_OCR_TIMEOUT_S | 60 / 30 | Бюджет одного вызова Model Gateway. |
| RAG_CONVERTER_MODEL_CONCURRENCY | 4 | Сколько картинок описывается одновременно. |

[MarkItDown](https://github.com/microsoft/markitdown) — ранее предложенный кандидат для текстовой части; у него есть потоковый convert_stream, но это само по себе не гарантирует все нужные свойства каждого обработчика. Допуск конкретного обработчика зависит от тестов таблиц, изображений, памяти и отсутствия записи оригинала. Установленная библиотека сама по себе не подтверждает эти свойства.

## Проверка профиля

| Вход | Ожидание |
| --- | --- |
| Заголовки и таблицы | Читаемый Markdown без потери значимых значений. |
| Скриншот/схема | OCR/описание, байты изображения и совпадающий плейсхолдер. |
| Картинка без текста | Пустой OCR допустим; VLM может дать содержательное описание. |
| Повреждение/неизвестный тип | Отказ, а не частично принятая редакция. |
| Зависание/превышение памяти | Управляемая остановка без accepted. |

Форматы, модели и лимиты — конфигурация испытанного профиля. До его проверки готовность приёма не объявляем.
