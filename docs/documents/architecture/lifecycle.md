:::warning Рабочая схема
Названия состояний описывают ход работы. Таймауты, число попыток и правила обработки окончательных ошибок уточним при реализации.
:::

## Вопрос и доставка

| Состояние | Кто и что фиксирует | Откуда продолжаем |
| --- | --- | --- |
| Принят | RAG API сохраняет вопрос, его место в порядке чата и запись outbox для `rag.questions`. После фиксации приём можно подтвердить. | Queue Relay отправляет сохранённое сообщение. Повтор входящего обновления относится к тому же запросу. |
| Обрабатывается | RAG Core берёт следующий вопрос чата и закрепляет поколение корпуса. | После сбоя Core повторяет обработку с Guardrails по тому же вопросу и поколению. |
| Результат готов | RAG Core одной транзакцией сохраняет итог и запись outbox для `rag.results` и снимает закрепление редакций. | Queue Relay публикует результат. RAG API использует сохранённый текст и источники. |
| Доставка ждёт повтора | RAG API сохраняет исход попытки и план повтора. При таймауте результат мог быть принят Telegram. | Повторяем отправку сохранённого результата до установленного предела. |
| Доставка завершена | RAG API фиксирует подтверждение, окончательную ошибку или неизвестный итог. Итог неизвестен, если подтверждения нет и хотя бы одна попытка могла дойти до Telegram. | Доставку следующего ответа в этом чате можно начать. |

Обработка и доставка идут в порядке приёма внутри чата. Следующий вопрос может обрабатываться после фиксации итога предыдущего. Его ответ ждёт, пока доставка предыдущего завершится или исчерпает попытки.

## Кто продолжает работу после рестарта

| Ситуация | Кто восстанавливает | Что происходит |
| --- | --- | --- |
| Штатный рестарт брокера или получателя | RabbitMQ | Долговечные очереди и сообщения, опубликованные с сохранением, переживают штатный рестарт при сохранном хранилище. При обрыве соединения неподтверждённые сообщения возвращаются к доставке. [Очереди RabbitMQ](https://www.rabbitmq.com/docs/queues) · [Подтверждения RabbitMQ](https://www.rabbitmq.com/docs/confirms) |
| Отправка из outbox осталась незавершённой | Queue Relay | При запуске и в обычной работе допубликовывает записи без сохранённого подтверждения отправки, включая прерванные попытки публикации. |
| Пришло время повтора или прервалась попытка приложения | RAG Core — обработка вопросов, RAG API — доставка в Telegram, Ingestion Worker — обработка документов и очистка | Каждый модуль через Runtime находит свою работу по состоянию PostgreSQL. Возобновляет этап или фиксирует итоговый сбой. Если нужно снова передать работу в очередь, записывает намерение в outbox. |
| Утрачено содержимое очередей RabbitMQ | Runtime и владельцы этапов | Runtime восстанавливает очереди. Владельцы заново ставят через outbox готовую незавершённую работу с учётом порядка, сроков и окна доставки последнего уведомления. Queue Relay публикует записи. [Правила восстановления](../infrastructure/postgresql/outbox.md#recover-pending-work) |

Проверку прерванных попыток выполняем при запуске и периодически. Повтор берёт работу после окончания предыдущей попытки или истечения срока, отведённого ей на выполнение. Если запоздавший обработчик вернётся, он уже не может зафиксировать результат этой попытки. Для Ingestion дополнительно требуется остановка зависшего процесса, а после неизвестного исхода записи в Qdrant — сверка. Готовый ответ при восстановлении идёт только в доставку. Исчерпание попыток завершает этап, чтобы освободить очередь чата или закреплённую редакцию.

## Загрузка и публикация

| Состояние | Кто и что фиксирует | Откуда продолжаем |
| --- | --- | --- |
| Загрузка принята | Ingestion Gateway сохраняет входной файл в рабочем томе, затем фиксирует редакцию с заданием и outbox для `ingestion.jobs`. | Queue Relay публикует задание. Ingestion Worker берёт задания последовательно. |
| Редакция готовится | Ingestion Worker готовит фрагменты, фиксирует ожидаемое число и начало записи в PostgreSQL. Перед публикацией сверяет полный набор точек. | Повтор использует то же задание и ID точек. При неизвестном исходе записи повтор и удаление ждут [операторской сверки](../infrastructure/qdrant/index.md#сверка-незавершённых-записей). |
| Редакция опубликована | Ingestion Worker переключает активную редакцию в PostgreSQL, обновляет поколение корпуса и сохраняет итог задания одной транзакцией. | Повтор видит готовый итог. Новые запросы выбирают новую редакцию. Временный файл можно удалить. |
| Прежняя редакция ждёт очистки | Ingestion Worker убирает её фрагменты, когда она уже неактивна и больше не нужна закрепившим её запросам. | Если очистка прервалась, её можно повторить отдельно от публикации. [Данные и версии](./data-and-versions.md) |

## Что происходит при сбое

| Точка сбоя | Поведение при восстановлении |
| --- | --- |
| Outbox зафиксирован, отправка в RabbitMQ прервалась | Queue Relay отправит запись снова. Если брокер уже принял первое сообщение, получатель распознает повтор по запросу или заданию и этапу. |
| Модель ответила, а итог в PostgreSQL ещё не записан | Core может снова вызвать модель по закреплённым редакциям. Для запроса фиксируется один итог и одна задача доставки. |
| Итог этапа записан, а подтверждение очереди потеряно | Получатель читает сохранённое состояние и подтверждает повтор без повторного выполнения завершённого перехода. |
| Запись точек началась, а Worker прервался до публикации | Поиск видит прежнюю редакцию. Сохранённый признак незавершённой записи блокирует повтор и обычную уборку до сверки. |
| Указатель в PostgreSQL уже переключён, worker перезапустился | Публикация считается завершённой. Worker убирает оставшийся временный файл и отдельно очищает старые чанки, когда их отпустят запросы. |
| Отправка в Telegram завершилась таймаутом | RAG API повторяет отправку того же результата. Если первая попытка уже дошла, пользователь может увидеть дубликат. |

Подтверждение сообщения следует за сохранённым итогом, зафиксированным планом повтора или проверкой, что уведомление уже не требует действий. Запоздавшая попытка не может перезаписать уже завершённый переход. [Очереди и доставка](./message-flow.md) · [Переходы RAG Core](../rag-core/flow.md#транзакции-и-повторы)
