## Как собирается ответ

1. Answer Generator формирует контекст в пределах бюджета модели. Вопрос и тексты фрагментов передаёт отдельно от системных инструкций. Если бюджет не позволяет включить ни одного фрагмента, сообщает о технической ошибке. В MVP Runtime выбирает провайдера, допущенного для общего корпуса. Если кейс задаст правила передачи на уровне отдельных документов, добавляем проверку до отправки контекста.
2. Answer Generator назначает вошедшим в контекст чанкам метки `S1`, `S2` и хранит соответствие меток и `chunk_id` на время вызова. Для ответа модель заполняет `kind: "answered"`, `answer_text` и список меток `citations`, а также cited_image_ids из допустимых ImageRef. Плейсхолдеры Markdown имеют вид `![Описание](image://<uuid>)`; ID в тексте и списке совпадают. Для нехватки данных возвращает `kind: "insufficient_evidence"`.
3. Answer Generator передаёт сообщения с сохранёнными ролями и `GenerationOptions` в [`Model Gateway.generate(messages, options, timeout_s=generation_timeout_s)`](../model-gateway/entrypoints.md#generate). Бюджет вызова и настройки вывода берёт из конфигурации Runtime. Gateway возвращает полный `ModelGenerationResult`, даже если провайдер использовал stream. При `length`/`filtered` генератор поднимает `StepError("generation_incomplete", False)`; при `completed` проверяет структуру JSON из `text` и переводит метки в `cited_chunk_ids`. Ответ без текста, без ссылочных меток или с неизвестной меткой считается ошибкой формата. Core собирает источники по ID, убирая повторы в порядке первого упоминания. Ссылки, названия и необязательные локаторы берёт из метаданных чанков; изображения — из их images.

В MVP отдаём цельный текст и отдельный список источников. RAG API отвечает за оформление списка в Telegram. Проверка меток подтверждает, что источник входил в контекст. Фактическая опора ответа на источники остаётся задачей промпта. [Итоги синка, D-05 и Q-10](../faq/drafts/architecture-team-sync.md)

Изображение разрешено цитировать только из фактически включённых в контекст чанков; соответствующий чанк должен входить в citations. Удаление фрагмента из контекста удаляет и его недоступные иначе ImageRef. Генератор не скачивает S3, не конвертирует исходники, не создаёт тикет и не вставляет произвольные ссылки вместо image_id. Нехватка подтверждений — типизированный insufficient_evidence, не техническая ошибка и не текст с выдуманным ответом.
