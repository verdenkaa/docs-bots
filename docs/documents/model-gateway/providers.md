:::warning
Production-модели и их ресурсы ещё требуют выбора и оценки. Для локальной проверки добавлен явный [профиль Ollama](./ollama.md); ни один backend не включается автоматически. Ниже описаны транспорт и точки подключения других backend.
:::

Публичные [восемь операций](./entrypoints.md) и [DTO](./contracts.md) сохраняются. Технические расширения находятся в app/rag/model_gateway/providers.py. Runtime выбирает bindings и координатор вызовов; бизнес-модули вызывают только операции Model Gateway.

## Локальный backend

Встроенный provider `local_process` запускает управляемые дочерние Python-процессы. Каждый исполнитель один раз вызывает фабрику backend, держит одну копию модели и последовательно выполняет inference. Число исполнителей роли равно ModelBinding.max_concurrency; независимые процессы Runtime имеют независимые пулы и расходуют RAM/VRAM отдельно. Импорт Gateway не загружает модели.

Задайте RAG_MODEL_BINDINGS и MODEL_GATEWAY_LOCAL_LOADERS как JSON. Пример одного embedding-профиля (имя модели и фабрика здесь условные):

~~~json
{
  "embedding": {
    "profile_id": "embedding-v1",
    "execution": "local",
    "provider": "local_process",
    "model_id": "chosen-model",
    "model_revision": "pinned-revision",
    "endpoint": null,
    "credential_env": null,
    "max_concurrency": 1,
    "embedding_dimensions": 768
  }
}
~~~

~~~text
MODEL_GATEWAY_LOCAL_LOADERS={"embedding-v1":"my_backends.embedding:create_model"}
MODEL_GATEWAY_CACHE_DIR=/var/lib/rag/models
~~~

Модуль my_backends должен быть установлен в том же окружении Python. Фабрика имеет интерфейс `create_model(*, binding, role, cache_dir)` и возвращает экземпляр `LocalModel`. Это обычный внутренний объект, не DTO. binding — проверенный ModelBinding; role — ModelRole; cache_dir — pathlib.Path к отдельному каталогу профиля на постоянном томе. Фабрика загружает закреплённую ревизию весов и проверяет совместимость настроек; она вызывается только в дочернем процессе. Установку SDK и доставку весов выполняет сборка выбранного backend. Скрытого выбора или скачивания произвольной модели у Gateway нет.

Backend реализует синхронный `invoke(operation, payload)` и при необходимости `close()`. invoke возвращает DTO результата либо словарь с его полями. close освобождает ресурсы и собственных исполнителей. Backend не должен отсоединять процессы-демоны от управляемого дерева/группы Runtime. Не переносите в backend бизнес-пороги, выбор редакций, SQL, публикацию очередей или повторы inference.

| Роль | operation и payload | Результат |
| --- | --- | --- |
| embedding | embed_texts: texts, purpose | EmbeddingResult, один вектор на текст в исходном порядке, закреплённая размерность. purpose различает query/document внутри профиля. |
| reranker | rerank: query, candidates | RerankResult, ровно одна оценка на индекс кандидата; Gateway возвращает scores в порядке индексов. |
| injection | classify_injection: text | InjectionResult: нормализованные label и необязательный score, без решения о допуске. |
| generation | generate: messages, options | ModelGenerationResult либо GenerationStream; решение о JSON и источниках у вызывающего модуля. |
| ocr | recognize_text: image | OcrResult; пустой распознанный текст допустим. |
| vision | describe_image: image | ImageDescription с непустым description. |

messages, options и image передаются как словари проверенных DTO; image.data — bytes. Все ответы содержат фактически использованный profile_id. Числа должны быть конечными. Gateway проверяет профиль, форму, размерность, количество и соответствие позиций до передачи ответа владельцу сценария. Для пустого embedding/rerank inference не выполняется, но роль должна быть готова.

Перед допуском работы проверяются все исполнители всех запрошенных ролей настоящим коротким пробным вызовом. При частичном сбое запуска весь созданный пул закрывается. После таймаута/отмены активный локальный исполнитель останавливается вместе с деревом дочерних процессов и заменяется с повторной проверкой готовности. Исходный запрос при этом не повторяется. На Linux дочерние процессы наследуют группу Runtime, поэтому общий супервизор Worker также может остановить их. На Windows используется taskkill /T /F. Запуск процессов проходит без видимых окон.

В дочернее окружение передаются системные пути, настройки кеша/CUDA и только явно названный credential_env. Секрет из общего файла под именем credential_env доступен адаптеру в окружении только на время жизненного цикла моделей; явно заданное окружение имеет приоритет. Значение секрета не входит в binding, командную строку или логи. Вывод backend подавляется, чтобы stdout модели не повреждал IPC и не раскрывал промпты. Собственную диагностику backend нужно организовать с теми же правилами приватности.

## Другой транспорт или внешний API

`ModelAdapter` — обычный абстрактный класс с execution="local" либо "remote" и async-методами start(), invoke(operation, payload, *, timeout_s), close(). start создаёт ресурсы, close обязан быть повторяемым и закрывать также частично созданные ресурсы. Фабрика `factory(binding, role)` должна быть быстрой и не выполнять загрузку весов/сетевые вызовы; ресурсы создаются в start. Все CPU-вызовы выносите из event loop.

Стандартный probe(operation, payload, *, timeout_s) вызывает invoke и возвращает список результатов. Адаптер с собственным пулом переопределяет probe и проверяет каждого исполнителя. Удалённый адаптер создаёт переиспользуемый async-клиент, нормализует формат провайдера и коды StepError, передаёт оставшийся срок серверу, закрывает stream и клиент. Закрытие соединения само по себе не доказывает остановку удалённого inference. Не добавляйте автоматический retry POST в SDK.

### <span className="operation-badge operation-badge--call">CALL</span> `register_provider`

~~~python
def register_provider(name: str, factory: Callable) -> None: ...
~~~

Регистрирует фабрику ModelAdapter до start_models. Callable импортируется из collections.abc. Имя соответствует `[a-z][a-z0-9_.-]{0,63}`; local_process зарезервировано. Конфликт имён, неверный вход и изменение работающего реестра дают model_configuration_error. Повтор той же фабрики до запуска допустим.

### <span className="operation-badge operation-badge--call">CALL</span> `unregister_provider`

~~~python
def unregister_provider(name: str) -> None: ...
~~~

Удаляет регистрацию до запуска или после успешного close_models; отсутствие имени допустимо. При работающем/незавершённо закрытом Gateway возвращает model_configuration_error.

Для отдельного процесса Runtime задайте MODEL_GATEWAY_PROVIDER_MODULES как JSON-список модулей. При явном start_models они импортируются и вызывается их синхронная функция register_providers(), регистрирующая фабрики. Не загружайте веса при импорте или в этом hook. Регистрация откатывается при неуспешном запуске; в работающем Gateway реестр заморожен.

## Сборка stream

Удалённый адаптер может вернуть `GenerationStream(profile_id, chunks)`, где chunks — async iterable. Локальный LocalModel использует синхронный iterable; сборка выполняется в дочернем процессе. Это технический объект, наружу всегда возвращается полный ModelGenerationResult.

Каждый элемент — mapping с text (строка, в том числе пустая); последний дополнительно содержит finish_reason из completed/length/filtered и необязательный usage по ModelUsage. События после терминального запрещены; EOF без него, неизвестный исход, неверный формат или превышение лимита дают ошибку. Текст при обрыве не возвращается как успешный результат. Пустой text при completed недопустим; при length/filtered сохраняется реальный сырой исход. Async stream закрывается также при отмене. Не делайте вывод о length только по числу токенов.

## Повторные вопросы и retry {#повторы}

Одновременные одинаковые вызовы в процессе присоединяются к одной задаче и не занимают дополнительные места очереди. Ключ включает binding целиком (включая профиль и ревизию), операцию и все проверенные входы: порядок текстов/сообщений, purpose, options, байты изображения. Различные промпты или purpose не объединяются. Каждый ожидающий получает собственную копию DTO и может отменить своё ожидание; пока остаются другие ожидающие, общая задача продолжается.

Runtime подключает PostgreSQL-координатор с технической таблицей model_calls через SQLAlchemy. Он добавляет в ключ устойчивый request_id либо job_id из контекста обработчика RabbitMQ. Номер попытки и ID доставки в ключ не входят. Повторы одной работы в нескольких процессах разделяют одного владельца inference и читают сохранённый проверенный результат; перезапуск Runtime его не теряет. Другие вопросы остаются самостоятельной работой: бизнес-кеш готового ответа находится в Exact Cache. Для прямого вызова без контекста используется пространство standalone.

Захват и сохранение результата выполняются короткими транзакциями с проверкой токена владельца; во время inference транзакция не удерживается. Результат сохраняется до ответа вызывающей стороне. Постоянные технические ошибки также воспроизводятся без повторного inference. Исходные тексты и промпты не сохраняются в журнале: ключ — хеш. Полный результат хранится в JSONB и требует того же ограничения доступа, что ответы в PostgreSQL.

Сбой/отмена после начала inference оставляет uncertain; аварийно погибший владелец может оставить executing. Такие записи не имеют автоматически истекающей аренды. Следующий вызов получает model_unavailable либо ожидает владельца в пределах своего timeout_s. Это сознательный выбор для исключения двойного вычисления при неизвестном исходе: безопасно совместить автоматический повтор и гарантию единственного удалённого inference без идемпотентности самого сервера невозможно. Для разблокировки оператор сначала подтверждает остановку прежних исполнителей и выполняет [процедуру Runtime](../infrastructure/runtime-entrypoints.md#журнал-модельных-вызовов). Удаление completed-записей прекращает гарантию воспроизведения для соответствующей истории; автоматического удаления журналов нет.

### <span className="operation-badge operation-badge--call">CALL</span> `configure_coordination`

~~~python
def configure_coordination(coordinator: object | None) -> None: ...
~~~

Сборка Runtime устанавливает экземпляр CallCoordinator до start_models; None выбирает память процесса. В работающем Gateway изменение запрещено (model_configuration_error). CallCoordinator — технический абстрактный класс: namespace() возвращает устойчивое пространство работы; async acquire(key, profile_id, role, operation) возвращает owned с token, done с value, busy или uncertain; complete(key, token, value) сохраняет результат с проверкой владельца; release(key, token, *, safe) удаляет только ещё не начатую работу, иначе блокирует повтор как неизвестный исход. Собственных обращений к PostgreSQL внутри Model Gateway нет.

Без Runtime используется память процесса: объединение текущих задач и ограниченный TTL-кеш результатов; перезапуск или вытеснение кеша разрешает новое вычисление. Такая конфигурация подходит для отдельной проверки backend, но не заменяет долговечную защиту retry в приложении.

## Настройки и проверка

Параметры читаются при start_models из окружения и .env в корне репозитория (либо файла RAG_ENV_FILE); окружение имеет приоритет. Некорректная конфигурация отклоняется без раскрытия значений.

| MODEL_GATEWAY_… | По умолчанию | Назначение |
| --- | --- | --- |
| QUEUE_SIZE | 32 | Ожидающие уникальные задачи на роль сверх max_concurrency. |
| STARTUP_TIMEOUT_S / SHUTDOWN_TIMEOUT_S | 120 / 15 | Общие бюджеты запуска/остановки Gateway. |
| STOP_GRACE_S | 1 | Ожидание штатного закрытия свободного локального исполнителя перед принудительной остановкой. |
| MAX_LOCAL_WORKERS | 4 | Верхняя граница max_concurrency локальной роли. Учитывайте RAM/VRAM каждой копии. |
| CACHE_DIR | /var/lib/rag/models | Постоянный том кеша backend. |
| LOCAL_MEMORY_BYTES | не задан | Опциональный RLIMIT_AS адресного пространства каждого Linux-исполнителя. Не заменяет лимиты RAM/GPU контейнера; совместимость с SDK проверяется отдельно. |
| MAX_BATCH_ITEMS / MAX_TEXT_CHARS | 128 / 1000000 | Число входов/messages и суммарная длина текстов. |
| MAX_IMAGE_BYTES / MAX_MESSAGE_BYTES | 20 MiB / 64 MiB | Бинарное изображение и сериализованный транспорт/ответ. |
| CACHE_SIZE / CACHE_TTL_S | 256 / 60 | Только standalone-кеш завершённых результатов в памяти. |
| COORDINATION_POLL_S | 0.1 | Интервал ожидания другого владельца. |
| LOCAL_LOADERS / PROVIDER_MODULES | пустая карта / список | Явные точки подключения backend. |

Из app/ выполните `python -m rag.runtime check-models` либо добавьте `--role embedding` (флаг повторяемый). Команда запускает только явно заданные bindings, проверяет все их роли и закрывает ресурсы; PostgreSQL для неё не нужен. Успех означает выполненный пробный inference и вывод карты роль → профиль. Пустая карта не подтверждает готовность бота. Необходимо отдельно проверить качество, пределы контекста, ресурсы и совместимость выбранного embedding-профиля с индексом. Тестовые backend из app/tests не являются production-моделями.
