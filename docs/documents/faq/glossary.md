## Система и модули {#modules}

| Термин | Что означает у нас | Где подробнее |
| --- | --- | --- |
| **RAG** · Retrieval-Augmented Generation | Ответ модели на основе найденных фрагментов документации с указанием источников. | [Архитектура](../architecture/index.md) |
| **MVP / первый срез** | Минимальный сквозной сценарий «загрузка документа → публикация → вопрос → ответ с источниками». | [Проверки среза](./mvp-checklist.md) |
| **Модульный монолит** | Общая кодовая база с модулями, разделёнными по ответственности и контрактам. Из неё запускаются `core` и `worker`. | [Сборка модулей](../architecture/module-composition.md) |
| **Модуль / компонент / сервис Compose** | Модуль задаёт область ответственности, компонент выполняет её часть, сервис Compose задаёт запускаемый контейнер. Один контейнер содержит несколько модулей. | [Карта модулей](../architecture/index.md#имена-модулей) |
| **RAG API** | Шлюз Telegram. Принимает обновления, регистрирует вопросы и доставляет сохранённые ответы. | [RAG API](../telegram/module/index.md) |
| **RAG Core** | Оркестратор вопроса. Вызывает проверку, кеш, поиск и генератор, сохраняет итог и намерение передать его в доставку. | [RAG Core](../rag-core/index.md) |
| **Guardrails** | Проверка исходного вопроса на prompt injection и подготовка нормализованного текста при допуске. В MVP проверяет только вопрос пользователя. | [Guardrails](../guardrails/index.md) |
| **Exact Cache** | Компонент RAG Core для повторного использования готового ответа по точному нормализованному вопросу и подходящему поколению корпуса. Хранилище — Redis. | [Exact Cache](../rag-core/exact-cache.md) |
| **Searcher** | Поисковый модуль. Возвращает фрагменты с метаданными только из переданного набора редакций. | [Searcher](../retrieval/index.md) |
| **Answer Generator** | Компонент RAG Core, который вызывает LLM по вопросу и найденному контексту, проверяет формат ответа и метки источников. | [Answer Generator](../rag-core/answer-generator.md) |
| **Ingestion** | Модуль приёма, подготовки, индексации и публикации документов. | [Ingestion](../ingestion/index.md) |
| **Ingestion Gateway** | Принимает поток файла, сохраняет временную загрузку и регистрирует редакцию с заданием. Внешний транспорт ещё выбираем. | [Gateway](../ingestion/gateway.md) |
| **Ingestion Worker** | Последовательный исполнитель заданий индексации. Готовит чанки, пишет точки, публикует редакции и выполняет уборку. | [Worker](../ingestion/worker.md) |
| **Model Gateway** | Общий модуль технических вызовов моделей: embedding, reranker, детектор инъекций и генерация. Выбор backend не меняет бизнес-контракты вызывающих модулей. | [Model Gateway](../model-gateway/index.md) |
| **Runtime** | Общий инфраструктурный модуль. Собирает реализации, подключает адаптеры хранилищ, запускает фоновые роли и восстановление. | [Runtime](../infrastructure/index.md) |
| **Queue Relay** | Фоновый компонент Runtime в `core`. Публикует готовые записи outbox в RabbitMQ для всех трёх маршрутов, включая задания `worker`. | [Queue Relay](../infrastructure/queue-relay.md) |
| **Gateway / шлюз** | Шлюз с явно названной ответственностью: RAG API — Telegram, Ingestion Gateway — загрузки, Model Gateway — обращения к локальным моделям/внешним API. | [Границы модулей](../architecture/index.md) |
| **Адаптер** | Реализация обращения к конкретному транспорту, хранилищу или провайдеру за согласованным Python-интерфейсом. | [Runtime](../infrastructure/index.md) |
| **Пайплайн / конвейер / шаг** | Упорядоченная обработка и один вызов внутри неё. Путь вопроса задаёт RAG Core, путь документа — Ingestion Worker. | [Путь вопроса](../rag-core/flow.md) |
| **Точка входа / контракт** | Именованная функция или HTTP-ручка и правила её вызова: вход, результат, ошибки и повторы. | [Шаблоны и теги](./index.md#как-дописывать-документацию) |
| **DTO** · Data Transfer Object | Согласованная структура передаваемых данных. Между Python-функциями — объект Pydantic, в очереди — JSON. | [Общие DTO](../rag-core/contracts.md) |
| **Заглушка / scaffold / mock** | Минимальная или тестовая реализация интерфейса. Каркас позволяет запустить роли, но не подтверждает работоспособность бизнес-сценария. | [Запуск каркаса](./container-manager.md#как-подключить-или-обновить-приложение) |

## Документы, корпус и версии {#documents}

| Термин | Что означает у нас | Где подробнее |
| --- | --- | --- |
| **Корпус / база знаний** | Набор документов, доступных боту для поиска. В каждом опубликованном составе у документа максимум одна видимая редакция. | [Данные и версии](../architecture/data-and-versions.md#как-меняется-версия-корпуса) |
| **Документ** | Самостоятельный источник со стабильным `document_id`, объединяющим все его редакции. Совпадение имён файлов не определяет идентичность. | [Идентичность документа](../ingestion/index.md#новый-документ-или-новая-редакция) |
| **Редакция** · document revision | Одна загруженная версия одного документа со своим `revision_id` и набором чанков. | [Ingestion](../ingestion/index.md) |
| **Активная / опубликованная редакция** | Редакция документа, видимая в текущем поколении корпуса после коммита публикации в PostgreSQL. | [Публикация](../ingestion/index.md#публикация) |
| **Поколение корпуса** | Номер версии всего опубликованного набора. Увеличивается при изменении состава, включая добавление документа. Для пустого корпуса равен `0`. | [Поколения](../architecture/data-and-versions.md#как-меняется-версия-корпуса) |
| **Закрепление поколения / pinning** | Сохранение поколения за начатым запросом. Повтор использует тот же состав, а нужные ему редакции защищены от очистки до фиксации итога. | [Закрепление и очистка](../architecture/data-and-versions.md) |
| **Интервал видимости** | Поколения, в которых редакция доступна: `[visible_from_generation, visible_until_generation)`. Верхняя граница не входит в интервал, пустая означает открытую границу. | [Схема версий](../infrastructure/postgresql/index.md#редакции-и-поколения) |
| **Публикация редакции** | Коммит PostgreSQL после готовности полного индекса: открыть новую редакцию, закрыть прежнюю и увеличить поколение одной транзакцией. | [Публикация Worker](../ingestion/worker.md#от-задания-до-публикации) |
| **Индексация** | Подготовка текста, разбиение на чанки, вычисление эмбеддингов и запись поисковых точек. Пока публикации нет, новая редакция поиску недоступна. | [Worker](../ingestion/worker.md) |
| **Инкрементальное обновление** | Подготовка точек изменённого документа рядом со старыми в общей коллекции. Остальные документы не требуют полной переиндексации. | [Замена редакции](../ingestion/index.md#пример-замены-редакции) |
| **Чанк / chunk / фрагмент** | Часть текста документа с локатором, если он известен. В Qdrant одному чанку соответствует одна точка с одним dense-вектором. | [Структура точки](../infrastructure/qdrant/index.md#структура-точки) |
| **Чанкинг / chunking / перекрытие** | Разбиение текста и, при необходимости, повторение части текста в соседних чанках. Границы, размер и перекрытие подбираем по кейсу. | [Подготовка текста](../ingestion/worker.md#подготовка-текста) |
| **Парсер / OCR** | Извлечение текста и структуры файла / распознавание текста на изображениях и сканах. Набор парсеров и необходимость OCR выбираем по документам кейса. | [Подготовка текста](../ingestion/worker.md#подготовка-текста) |
| **Источник / ссылка на источник** | Документ, подтверждающий ответ, и его ссылочные метаданные. `source_name` — подпись, `source_url` — адрес при наличии. | [SourceRef](../rag-core/contracts.md#общие-dto) |
| **Локатор** · SourceLocator | Место внутри источника: `page` с нумерацией от 1 и/или `section`. При неизвестном месте используется `None`. | [Подготовка текста](../ingestion/worker.md#подготовка-текста) |
| **Временная загрузка / staging / upload spool** | Файл и его метаданные на постоянном рабочем томе до завершения задания. После публикации или окончательного сбоя удаляются. | [Временный том](../infrastructure/upload-spool/index.md) |
| **Манифест загрузки** · `manifest.json` | Имя файла и URL источника, сохранённые рядом с временным файлом `source`. | [Формат загрузки](../infrastructure/upload-spool/index.md#запись-временного-файла) |
| **Манифест редакции** · RevisionManifest | `revision_id` и ожидаемое число чанков для проверки полного набора детерминированных ID. Используется при восстановлении индекса. | [Манифесты редакций](../infrastructure/postgresql/ingestion.md#list-required-revision-manifests) |
| **Очистка / GC** · Garbage Collection | Удаление ненужных точек и временных загрузок. Старые точки удаляются после освобождения закреплений; уборка файлов выполняется независимо. | [Очистка Worker](../ingestion/worker.md#очистка-после-обработки) |
| **Сверка незавершённой записи** | Операторская процедура при неизвестном исходе записи Qdrant. Исключает старые операции, удаляет частичные точки и снимает блокировку повтора. | [Процедура сверки](../infrastructure/qdrant/index.md#сверка-незавершённых-записей) |

**Пример.** Документ A обновился с редакции R1 до R2 — поколение всего корпуса сменилось с 41 на 42. Документ B остался прежним. Начатый запрос поколения 41 использует A/R1 и B, новый запрос поколения 42 — A/R2 и B.

| `run_id` | UUID отдельного запуска обработчика в логах. Связывает его события `started` и `finished`. | [Формат логов](./logging.md#общий-формат) |
| `attempt_no` / `deadline_at` | Номер попытки на текущем этапе / её крайний срок. Номера обработки и доставки рассматриваем отдельно. | [Общие DTO](../rag-core/contracts.md#общие-dto) |
| `resume_at` / `retry_at` | Поле БД со временем готовности или сроком активной попытки / назначенное время следующей попытки в вызове. Время передаётся в UTC. | [Поля запроса](../infrastructure/postgresql/index.md#rag_requests) |
| `available_at` / `published_at` | Момент готовности outbox к публикации / момент фиксации подтверждённой публикации. Ни одно поле не означает завершение обработки. | [Outbox](../infrastructure/postgresql/index.md#outbox) |

| `expected_chunk_count` | Ожидаемое число чанков, сохранённое до первой записи точек. Вместе с ID редакции задаёт полный ожидаемый набор ID. | [Проверка полноты](../infrastructure/qdrant/index.md#восстановление-индекса) |
| `qdrant_write_pending` | Сохранённый признак начатой записи. Пока он установлен, повтор индексации и обычная очистка этой редакции заблокированы. | [Неизвестный исход записи](../ingestion/worker.md#запись-в-qdrant-с-неизвестным-исходом) |
| `raw_question` / `question_text` | Исходный вопрос в DTO RAG Core / тот же исходный текст в PostgreSQL. | [Общие DTO](../rag-core/contracts.md#общие-dto) |
| `normalized_question` / `query` | Допущенный текст из Guardrails / имя параметра этого текста в последующих шагах. Преобразования должны сохранять смысл. | [Нормализация](../guardrails/index.md#нормализация) |
| `cited_chunk_ids` / `citations` | ID использованных чанков в результате генератора / метки `S1`, `S2` в ответе модели, преобразуемые Answer Generator в ID. | [Сборка ответа](../rag-core/answer-generator.md#как-собирается-ответ) |
| `compare_token` | Непрозрачный токен прочитанного значения Redis для условного удаления. Защищает новое значение от удаления старым запросом. | [Контракты Redis](../infrastructure/redis/contracts.md) |

## Поиск, генерация и кеш {#retrieval}

| Термин | Что означает у нас | Где подробнее |
| --- | --- | --- |
| **Retrieval / релевантность** | Поиск подходящих вопросу фрагментов / их соответствие вопросу. Непустая выдача ещё не доказывает достаточность данных для ответа. | [Конвейер поиска](../retrieval/pipeline.md) |
| **Эмбеддинг / embedding / dense-вектор** | Числовое представление текста для поиска по смыслу. Вопросы и чанки кодируются совместимой версией одной модели. | [Dense-поиск](../retrieval/pipeline.md) |
| **Dense-поиск / косинусная метрика** | Поиск по близости плотных векторов / выбранный способ их сравнения в Qdrant. | [Конфигурация Qdrant](../infrastructure/qdrant/index.md#запуск) |
| **BM25** | Лексический поиск по словам текста чанка. В текущем кандидате использует текстовый индекс payload-поля `text`. | [Конвейер](../retrieval/pipeline.md) |
| **Токенизация / стемминг** | Выделение текстовых единиц для индекса / приведение словоформ к основе. Настройки проверяем на русском тексте, кодах и версиях. | [Оценка поиска](../retrieval/evaluation.md#как-выбрать-профиль) |
| **Гибридный поиск** | Объединение смыслового dense-поиска и лексического BM25. | [Конвейер](../retrieval/pipeline.md) |
| **RRF** · Reciprocal Rank Fusion | Объединение списков кандидатов по их позициям. Итоговый балл не является вероятностью правильного ответа. | [Объединение выдачи](../retrieval/pipeline.md) |
| **Reranker / reranking** | Модель повторной оценки пар «вопрос — чанк». Меняет порядок в найденном пуле, если шаг включён в профиль. | [Конвейер](../retrieval/pipeline.md) |
| **Профиль поиска** | Выбранные при запуске модели, ветки поиска, reranker и параметры отбора. Конкретный вариант выбираем замерами. | [Выбор профиля](../retrieval/evaluation.md#как-выбрать-профиль) |
| **Пул кандидатов / `candidate_limit` / `top_k`** | Фрагменты до окончательного отбора / предел получаемых кандидатов / максимум фрагментов итоговой выдачи. | [Конвейер](../retrieval/pipeline.md) |
| **`score` / порог релевантности** | Балл поиска или переоценки / подобранная граница отбора. Значение зависит от профиля и не заменяет проверку достаточности контекста. | [Оценка поиска](../retrieval/evaluation.md) |
| **Коллекция / точка / payload / payload-индекс** | Набор точек Qdrant / запись чанка / её текст и метаданные / индекс для фильтрации или текстового поиска по этим полям. Коллекция MVP — `document_chunks`. | [Qdrant](../infrastructure/qdrant/index.md) |
| **Match Any / `prefetch` Qdrant** | Фильтр принадлежности `revision_id` разрешённому набору / предварительная ветка выборки кандидатов. Один фильтр применяется к обеим веткам гибрида. | [Фильтрация поиска](../retrieval/pipeline.md) |
| **LLM** · Large Language Model | Языковая модель, которой Answer Generator передаёт вопрос и разрешённый контекст. Провайдер и модель выбираются по кейсу. | [Генератор](../rag-core/answer-generator.md) |
| **Промпт / системный промпт / контекст** | Входные инструкции модели / правила её поведения / найденные фрагменты как данные для ответа. Документы передаются отдельно от инструкций. | [Генератор](../rag-core/answer-generator.md#как-собирается-ответ) |
| **Токен / бюджет контекста и вывода** | Единица текста модели / пределы передаваемого и генерируемого текста. Это отдельное понятие от токена доступа Telegram. | [Бюджет генерации](../rag-core/answer-generator.md) |

| **Prompt injection** | Попытка через текст изменить инструкции или поведение модели. Guardrails допускает либо отклоняет вопрос до чтения кеша и поиска. | [Guardrails](../guardrails/index.md) |
| **Попадание / промах кеша** · cache hit / miss | Получен пригодный готовый ответ / нужно идти через поиск и генерацию. Недоступность Redis обрабатывается как промах. | [Exact Cache](../rag-core/exact-cache.md) |

| **TTL** · Time To Live | Срок хранения записи Redis для освобождения памяти. Проверка актуальности ответа выполняется по поколению корпуса. | [Redis](../infrastructure/redis/index.md) |
| **BGE-M3 / BGE Reranker v2 M3** | Кандидаты из прототипа Ромы для эмбеддингов / переоценки. Окончательный выбор и лимиты ещё требуют проверки на кейсе. | [Модели поиска](../retrieval/pipeline.md) |

## Очереди, попытки и доставка {#queues}

| Термин | Что означает у нас | Где подробнее |
| --- | --- | --- |
| **Брокер / RabbitMQ / AMQP** | Сервер доставки уведомлений / выбранный брокер / протокол взаимодействия с ним. Содержимое вопроса и итог читаются из PostgreSQL. | [RabbitMQ](../infrastructure/rabbitmq/index.md) |
| **Уведомление / сообщение очереди** | Ссылка `request_id` либо `job_id`, побуждающая получателя проверить работу в PostgreSQL. | [Формат сообщений](../infrastructure/rabbitmq/index.md#структура-сообщения) |
| **Задание / работа** | Сохранённое состояние этапа, которое выполняет обработчик. Одну работу могут сопровождать несколько уведомлений и попыток. | [Состояния и сбои](../architecture/lifecycle.md) |
| **Outbox / transactional outbox** | Записи намерения отправить уведомления. Создаются в PostgreSQL одной транзакцией с прикладным переходом, затем публикуются Relay. | [Outbox](../infrastructure/postgresql/outbox.md) |
| **Producer / publisher / consumer / handler** | Владелец, создающий работу / издатель уведомления, у нас Relay / потребитель очереди / вызываемый им обработчик. | [Поток сообщений](../architecture/message-flow.md) |
| **`rag.questions` / `rag.results` / `ingestion.jobs`** | Маршруты обработки вопроса Core / доставки сохранённого итога RAG API / индексации документа Worker. | [Таблица маршрутов](../architecture/message-flow.md#маршруты-rabbitmq) |
| **Exchange / routing key / `mandatory`** | Узел маршрутизации RabbitMQ / ключ назначения / флаг возврата немаршрутизированного сообщения издателю. | [Публикация](../infrastructure/rabbitmq/index.md#подтверждения-и-восстановление) |
| **Publisher confirm** | Подтверждение брокером публикации. Relay отмечает `published_at` после него и проверки маршрутизации. | [Публикация RabbitMQ](../infrastructure/rabbitmq/index.md#подтверждения-и-восстановление) |
| **ACK / `ack` / consumer acknowledgement** | Подтверждение потребителем уведомления после сохранённого перехода или проверки, что работа сейчас не требуется. Не обязательно означает успешный ответ пользователю. | [ConsumeDecision](../rag-core/contracts.md#очередь-и-готовый-результат) |
| **`retry_broker` / повторная доставка брокером** | Решение при неизвестном состоянии или коммите PostgreSQL. Адаптер с задержкой возвращает неподтверждённое уведомление в очередь. | [Адаптер RabbitMQ](../infrastructure/rabbitmq/contracts.md#доставка-уведомлений) |
| **Прикладной повтор / retry / backoff** | Новая попытка этапа, запланированная в PostgreSQL через outbox / повтор / увеличение задержки между повторами. | [Повторы Core](../rag-core/flow.md#транзакции-и-повторы) |
| **Prefetch RabbitMQ** | Предел сообщений у потребителя до подтверждения. Для Ingestion — `1`. Отличается от `prefetch` поискового запроса Qdrant. | [RabbitMQ](../infrastructure/rabbitmq/index.md#подтверждения-и-восстановление) |
| **Попытка / claim** | Один запуск этапа с номером и сроком / атомарное взятие работы через PostgreSQL с проверкой порядка и состояния. | [Переходы Core](../rag-core/flow.md#транзакции-и-повторы) |
| **Deadline / таймаут** | Общий крайний срок попытки / предел отдельного ожидания или вызова. Истечение срока в БД само по себе не останавливает вычисление. | [Остановка Worker](../ingestion/worker.md#срок-попытки-и-остановка-процесса) |
| **Супервизор** | Отдельный процесс Runtime, контролирующий потребителя Ingestion и его потомков. При зависании завершает их группу через `SIGTERM`, затем `SIGKILL`. | [Протокол остановки](../ingestion/worker.md#срок-попытки-и-остановка-процесса) |
| **Идемпотентность / дедупликация** | Безопасность повторного исполнения операции / распознавание уже принятого события. Повтор Telegram распознаётся по `update_id`, повтор очереди — по состоянию работы. | [Сохранение и повторы](../architecture/lifecycle.md) |
| **Порядок внутри чата / FIFO** | Приём, обработка и доставка соблюдают порядок `request_id` в чате. Порядок прихода уведомлений из RabbitMQ сам по себе его не обеспечивает. | [Очередность](../architecture/message-flow.md#порядок-и-повторы) |
| **Backpressure / лимит незавершённой работы** | Ограничение приёма при перегрузке. Учитываются все принятые вопросы до окончательного исхода доставки, включая уже опубликованные уведомления. | [Приём RAG API](../telegram/module/queue-processing.md) |
| **Окно доставки уведомления** | Пауза после публикации, в течение которой восстановление не создаёт лишнее уведомление для той же работы. | [Восстановление](../infrastructure/postgresql/outbox.md#recover-pending-work) |
| **Неизвестный исход / uncertain** | Внешнее действие или коммит могли состояться, хотя подтверждение не получено. Действие выясняется по сохранённому состоянию либо отдельной сверкой. | [Сбои](../architecture/lifecycle.md#что-происходит-при-сбое) |
| **At-least-once / exactly-once** | Возможность повторной доставки / однократность эффекта. Повторы уведомлений допускаются, а отправка Telegram после таймаута может дать дубль. | [Доставка](../telegram/module/queue-processing.md#сбои-и-повторы) |
| **Durable queue / persistent message** | Очередь / сообщение с настройкой сохранения для штатного рестарта при сохранном хранилище брокера. | [RabbitMQ](../infrastructure/rabbitmq/index.md#запуск) |

## Состояния и исходы {#states}

Одинаковое значение, например `queued` или `accepted`, читаем вместе с владельцем и типом DTO.

| Обозначение | Значение | Где подробнее |
| --- | --- | --- |
| Запрос: `queued` → `processing` → `ready_to_deliver` | Ожидает обработки → активная попытка Core → итог сохранён и ожидает доставки. Повтор возвращает в ожидание. | [Состояния запросов](../infrastructure/postgresql/index.md#вопросы-и-доставка) |
| Доставка: `delivering` → `delivered` / `delivery_failed` / `delivery_unknown` | Отправка выполняется → подтверждена / окончательно не удалась без неоднозначности / итог остался неизвестным. | [Переходы доставки](../infrastructure/postgresql/rag-api.md#complete-delivery) |
| Редакция: `queued` / `indexing` / `published` | Задание ждёт → индексируется → опубликовано. | [Контракты индексации](../infrastructure/postgresql/ingestion.md) |
| Редакция: `failed` / `retired` / `deleting` / `cleaned` | Подготовка завершилась сбоем / редакция выведена из активного состава / точки удаляются / удалены, метаданные в PostgreSQL сохранены. | [Очистка](../infrastructure/postgresql/cleanup.md) |
| Guardrails: `allowed` / `blocked` / `invalid_input` / `detector_unavailable` | Допуск с нормализованным вопросом / блокировка / некорректный ввод / технический сбой проверки. | [Контракт проверки](../guardrails/entrypoints.md#check-question) |
| Генерация: `answered` / `insufficient_evidence` | Ответ с ID использованных чанков / недостаточно подтверждения для ответа. | [Контракт генератора](../rag-core/answer-generator-entrypoints.md#generate-answer) |
| Приём Telegram: `accepted` / `duplicate` / `ignored` / `invalid_update` / `retry_later` | Зарегистрирован / принят ранее / вне сценария / некорректен / нужен повтор приёма. | [Контракт приёма](../telegram/module/entrypoints.md#handle-telegram-update) |
| Загрузка: `accepted` / `rejected` | Задание зафиксировано, индексация впереди / загрузка отклонена с кодом причины. | [Контракт загрузки](../ingestion/entrypoints.md#accept-upload) |
| Отправка: `sent` / `failed`, `retryable`, `uncertain` | Подтверждена / не подтверждена; признаки возможности повтора и того, что сообщение могло дойти. | [SendResult](../telegram/module/entrypoints.md#send-answer) |
| `delivery_uncertain` | Сохранённая неоднозначность хотя бы одной попытки отправки. Учитывается при окончательном исходе без подтверждения. | [rag_requests](../infrastructure/postgresql/index.md#rag_requests) |
| `length_fallback` | Короткое резервное сообщение при слишком длинном ответе. Отправляется в рамках той же доставки. | [Правила send_answer](../telegram/module/entrypoints.md#send-answer) |

## Прежние и неоднозначные обозначения {#old-names}

Исторические документы сохраняем в исходном виде. Эти соответствия помогают их читать, но не вводят старые поля или дополнительные модули в MVP.

| Встречается в черновиках | Как читать в текущей документации |
| --- | --- |
| `Retrieval`, `Retrieval / Rerank` | Поисковая зона нынешнего **Searcher**. Слово retrieval также обозначает сам процесс поиска. |
| `Generation`, `Answer Core` в обзоре репозиториев | Генерация и работа с доказательствами, описанные сейчас у **Answer Generator** и в сборке результата **RAG Core**. Отдельного модуля Answer Core в текущей карте нет. |
| `Telegram Gateway`, общий `Gateway` | Для Telegram используем **RAG API**, для документов — **Ingestion Gateway**. |
| `Ingestion API` | Прежнее название входа загрузки. Сейчас **Ingestion Gateway** с Python-входом `accept_upload`; наличие слова API не задаёт HTTP-ручку. |
| `L1`, `L2`, `L2 Cache`, `Exact + Canonical` | Ранние уровни кеша. Для MVP объединены в **Exact Cache** с проверенной нормализацией и поколением. |
| `L3`, `Semantic Cache` | Идея семантического переиспользования. В основном пути MVP не включена. |
| `knowledge release`, релиз базы знаний | В старых схемах — согласованный состав редакций. В текущей модели говорим **поколение корпуса**. Релиз приложения означает версию кода и образов. |
| `active_release`, `release_id`, `knowledge_release_id` | Прежние обозначения версии опубликованного состава. В текущей схеме — `corpus_state.generation` и связанные поля поколения. |
| `visible_from`, `visible_until` у чанка | Ранний вариант видимости. Сейчас интервалы хранятся в **document_revisions** в PostgreSQL, а Qdrant фильтруется по `revision_id`. |
| `is_active` в учебном прототипе Qdrant | Признак из прототипа, заменённый набором закреплённых редакций. Текущий поиск по одному этому флагу не строим. |
| `Evidence ID` | Идентификатор подтверждающего фрагмента. В текущем контракте — `chunk_id`; временная метка модели `S1` отдельно преобразуется в него. |
| `Version Garbage Collector` | Зона отложенной очистки редакций. Сейчас её выполняет **Ingestion Worker** через Runtime. |
| `worker`, «воркер», «под» без уточнения | Может означать сервис `worker`, Ingestion Worker или HTTP-процесс. В наших схемах используем Compose-контейнеры; Kubernetes-поды не предусмотрены. |
| `quadrant`, `Scearcher`, `posgres` | Опечатки. Принятые имена — **Qdrant**, **Searcher**, **PostgreSQL**. |

## Термины возможных расширений {#extensions}

Это словарь для чтения [оптимизаций](./optimization-and-features.md), [чек-листа кейса](./case-checklist.md) и исследований. Он не меняет выбранный состав MVP.

| Термин | Смысл и текущий статус |
| --- | --- |
| **Semantic Cache** | Кеш ответов по похожим вопросам. Требует проверки эквивалентности, особенно отрицаний, сущностей и версий. |
| **Embedding Cache / Retrieval Cache / кеш reranker** | Переиспользование векторов / найденных фрагментов / результатов переоценки с учётом модели, состава и профиля. |
| **Singleflight** | Один общий поиск или вызов LLM для одновременно пришедших одинаковых запросов с совместимым контекстом. Итоги запросов и порядок доставки сохраняются отдельно. |
| **Safe Text Normalization / лемматизация / алиасы / канонический ключ** | Проверенные преобразования текста / словарные формы / альтернативные имена / ключ по смысловым частям. Расширение совпадений требует проверки ложных попаданий. |
| **Static Intent Cache / Direct Retrieval Answer / Negative Result Cache** | Готовые реплики по типу обращения / ответ напрямую из проверенного источника / кеш проверенного отсутствия данных. |
| **Прогрев кеша / предрасчёт FAQ / Offline Preprocessing** | Подготовка часто нужных ответов или производных данных заранее, вне пути пользовательского вопроса. |
| **Version-Aware / Policy-aware Cache** | Кеш, учитывающий версию и влияющую на ответ политику доступа. Поколение уже проверяется в MVP; разделение по правам зависит от кейса. |
| **Prompt Optimization / Output Token Optimization / Prompt Caching** | Сокращение и настройка входа / ограничение вывода / повторное использование вычислений стабильного префикса провайдером. |
| **KV cache** | Внутренний кеш состояний attention языковой модели. Его применение зависит от модели и провайдера; это отдельное понятие от Redis и готового ответа Exact Cache. |
| **Query rewrite / Context fingerprint / Context-Aware Retrieval** | Переписывание вопроса / отпечаток влияющей на него истории / поиск с учётом диалога. В MVP каждый вопрос самостоятельный. |
| **Streaming / draft-first** | Показ ответа по частям / показ временного черновика до итогового текста. MVP отправляет готовый ответ целиком. |
| **Concurrency limiting / bounded queue / jitter** | Ограничение параллельных вызовов / вместимости очереди / случайная добавка к задержке повтора для разнесения всплесков. |
| **ACL / RBAC / Identity Provider / SSO** | Правила доступа / доступ по ролям / источник идентичности / единый вход. Конкретная модель закрытых документов выбирается по кейсу. |
| **Revocation / DLP / External Data Policy / Secure Citation Resolver** | Отзыв доступа / предотвращение утечек / правила передачи внешним сервисам / проверяемая выдача источников по ссылке. Условия определяет кейс. |
| **pgvector / FTS / sparse / multivector / MaxSim / CAG** | Альтернативы из исследований: векторное расширение PostgreSQL / полнотекстовый поиск / разреженные и многовекторные представления / сопоставление наборов векторов / подход с заранее подготовленным контекстом модели. Не выбранные компоненты текущего MVP. |
| **Evidence Recall@k / correctness / citation support / refusal** | Метрики из исследований: полнота подтверждающих фрагментов в первых k / правильность ответа / поддержка утверждений источниками / корректность отказа. Методику замера нужно задавать явно. |
| **Source-detection lag / publish lag / stale dispatch** | Время обнаружения правки источника / задержка её публикации / отправка ответа с устаревшими данными. Измеряемые границы зависят от сценария обновления. |
| **Rust / PyO3 / FFI / Python-first** | Язык для возможного ускорения вычислений / связывание Rust с Python / граница вызова нативного кода / старт на Python с оптимизацией по замерам. |
| **`CANDIDATE`, `CONDITIONAL`, `DEPRECATED_FOR_CASE`** | В исследованиях: предложение / вариант при выполнении условия / исключение из состава выбранного кейса. Эти пометки не означают утверждённое требование MVP. |
