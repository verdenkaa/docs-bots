# Навигация по проекту

Telegram RAG-бот для ответов по документации. В `app/` пока находится каркас: прикладные операции могут быть заглушками. Начинайте с `README.md` и `docs/documents/architecture/index.md`.

## Где что лежит

- `app/rag/` — Python-код: `rag_api/` — Telegram и результаты, `rag_core/` — сценарий ответа и кэш, `guardrails/` — проверки, `searcher/` — поиск, `ingestion/` — загрузка и индексация, `model_gateway/` — вызовы моделей, `runtime/` — инфраструктурные адаптеры. Общие DTO — `dto.py` и `contracts.py`; тесты — `app/tests/`. Соответствие функций и контрактов указано в `app/README.md`.
- `container-manager/` — инструмент для людей. Для агента там нет полезных материалов: не просматривайте и не изменяйте этот каталог.
- `docs/` — сайт документации; публикуемые страницы находятся в `docs/documents/`. Правила работы с ними — в `docs/AGENTS.md`.

## Документация

- `docs/documents/architecture/` — устройство MVP, потоки, жизненный цикл, данные и композиция модулей.
- `docs/documents/telegram/` — Telegram API, обработка сообщений и HTTP-эндпоинты; код — `app/rag/rag_api/`.
- `docs/documents/rag-core/` — сценарий ответа, генератор и кэш.
- `docs/documents/guardrails/` — проверки входящих вопросов.
- `docs/documents/retrieval/` — поиск и его оценка; код — `app/rag/searcher/`.
- `docs/documents/ingestion/` — загрузка и индексация документов.
- `docs/documents/model-gateway/` — вызовы и жизненный цикл моделей.
- `docs/documents/infrastructure/` — запуск и контракты PostgreSQL, RabbitMQ, Redis, Qdrant, upload spool и Queue Relay.
- `docs/documents/faq/` — глоссарий, DTO, логирование, окружение и чек-листы; `docs/documents/faq/drafts/` — исследования и рабочие обсуждения. Принятые решения команды сверяйте со столбцом «Итог» в `docs/documents/faq/drafts/architecture-team-sync.md`.

## Правила работы

- Перед изменением изучите документацию владельца и связанные вызовы; сохраняйте границы модулей. Не считайте черновые исследования утверждёнными требованиями, а предположения обозначайте явно.
- Изменять контракты, включая сигнатуры и DTO, без явного указания пользователя запрещено. При разрешённом изменении синхронизируйте вызывающие стороны, документацию и тесты контрактов. DTO наследуют `rag.dto.DTO` (Pydantic v2); вход на границах валидируется явно. Подробности — `docs/documents/faq/dto.md`.
- Вызовы моделей выполняйте через Model Gateway; Qdrant получает готовые векторы. Не запускайте сервисы и не загружайте модели при импорте модулей.
- Сохраняйте существующие пользовательские изменения и секреты; не включайте реальные ключи и локальные `.env` в репозиторий.
- Проверяйте изменения подходящими тестами: для приложения из `app/` — `python -m unittest discover -s tests -v`; для сайта из `docs/` — `npm test` и при изменениях документации `npm run build`. Если проверка недоступна, сообщите об этом.
