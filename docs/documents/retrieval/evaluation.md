:::warning План проверки
В материалах прототипа есть скрипты сравнения. Результаты для корпуса кейса и целевого сервера ещё предстоит получить.
:::

## Что взяли из прототипа

| Материал Ромы | Что показывает |
| --- | --- |
| `day1`–`day2` | Точки Qdrant, фильтрацию и dense-поиск по эмбеддингам. |
| `day3/day3_qdrant.py`, `day4/day4_qdrant.py` | Сравнение dense, BM25 и RRF на вопросах с ожидаемым разделом. В `day4` добавлены reranker и замеры времени. |
| `day5/database.py` | Пример подготовки коллекции, загрузки эмбеддингов и текстового индекса. Рабочие параметры индекса сверяем с версией сервера и клиента. |
| `day6/app/retrieval/`, `day6/app/services/rag_service.py` | Выделение поиска и reranker в отдельные функции, вызов из координатора и передача фрагментов генератору. |

В приложении сохраняем разделение этапов из `day6`. Коллекцию готовит Runtime, чанки пишет Ingestion Worker, RAG Core вызывает Searcher напрямую. Учебный `is_active` заменяем фильтром по закреплённым `revision_id`.

## Как выбрать профиль

На одном корпусе сравниваем dense, BM25, гибрид с RRF и тот же гибрид с reranker. Для каждого вопроса отмечаем чанки, которые действительно подтверждают ответ. Включаем точные коды и номера версий, перефразировки, русские словоформы, похожие разделы разных документов и вопросы без ответа в корпусе. У BM25 отдельно сравниваем токенизацию и русский стемминг на словах и кодах.

- **Качество.** На одинаковом `top_k` считаем долю вопросов с подходящим чанком в выдаче и средний обратный ранг первого подходящего чанка. Для вопросов без ответа отдельно проверяем, как часто нерелевантный контекст приводит к неподтверждённому ответу. Если вводим порог, проверяем его и на вопросах с ответом, чтобы измерить долю ошибочных отсевов.
- **Время.** Отдельно измеряем эмбеддинг вопроса, запрос Qdrant и reranker. Сравниваем p50 и p95 всего поиска на целевом сервере с прогретыми моделями при одинаковой нагрузке. Reranker включаем в рабочий профиль, если прибавка в качестве оправдывает его задержку.
- **Границы.** Проверяем ноль и одного кандидата, пустой набор редакций и отказ Qdrant или модели. При публикации новой редакции старый запрос должен получать только свой набор, новый — новый набор. Проверку выполняем отдельно для dense и BM25 и повторяем через гибридный запрос.
