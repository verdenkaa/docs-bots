# Структура документации

- Все публикуемые страницы хранятся только в `docs/documents/`. Конфигурация сайта и инструкции остаются в `docs/`.
- Каждая папка первого уровня в `documents/` — отдельный раздел в шапке со своим боковым меню. Имена папок: латиница в нижнем регистре, цифры и дефисы; начинать с буквы (`drafts`, `architecture`). Не размещайте страницы непосредственно в `documents/`.
- В каждом разделе обязателен файл `_category_.yml` с непустым `label` (название в интерфейсе) и числовым `position` (порядок в шапке). Используйте разные позиции. Раздел появляется автоматически, править `docusaurus.config.js` и `sidebars.js` для его добавления не нужно.

```yaml
label: Черновики
position: 1
```

- Вкладка раздела ведёт к первому документу его бокового меню. Для вводной страницы используйте `index.md` с `sidebar_position: 1`. Папки без документов скрываются из шапки; чтобы показать пока пустой раздел, добавьте `index.md` с коротким текстом-заглушкой. Для верхнего уровня не задавайте `link`, `collapsed` и другие настройки категорий: здесь читаются только `label` и `position`.
- Документы — `.md` или `.mdx` внутри раздела. В начале файла добавляйте YAML front matter:

```markdown
---
title: Название документа
sidebar_position: 1
---

Текст документа.
```

- Подпапки любой глубины становятся вложенными категориями бокового меню своего раздела, а не новыми вкладками в шапке. Для управления ими добавляйте собственный `_category_.yml`:

```yaml
label: Интеграции
position: 2
collapsed: true
link:
  type: generated-index
  title: Интеграции
```

- Вложенная категория должна содержать документы. `link` можно опустить. Для ссылки категории на конкретный документ используйте `link: {type: doc, id: index}`, если в этой папке есть `index.md`.
- YAML: UTF-8, отступы пробелами (обычно два), без табуляции. Строки с `: ` или `#` заключайте в кавычки. Не дублируйте ключи.
- Не задавайте одинаковые `slug` разным страницам. Главный адрес `/` ведёт на «Архитектуру MVP» (`/architecture/`). URL документов создаются по пути внутри `documents/`. Избегайте абсолютного `slug` без необходимости.
- После добавления раздела или изменения `_category_.yml` перезапустите локальный сервер. Проверьте шапку, боковое меню и ссылки; перед публикацией выполните `npm run build` из `docs/`.

## Как вести рабочие разделы

- В «Архитектуре» держите карту системы и общие правила MVP. В разделе модуля опишите его границу, входы и результаты операций, важные ошибки и открытые решения. В FAQ собирайте рабочие справки, проверки и ссылки на исследования.
- По решениям команды сверяйтесь со столбцом «Итог» в `documents/faq/drafts/architecture-team-sync.md`. Если текст и схемы выше таблиц расходятся с итогом, используйте итог. Новые предположения помечайте явно.
- Сразу после front matter каждой новой или обновляемой незавершённой страницы ставьте `:::warning`. Коротко укажите, что ещё нужно уточнить.
- В «Архитектуре» описывайте порядок действий, владельцев данных и обмен между модулями. Контракты операций, сигнатуры и DTO ведите в разделах модулей. Явно различайте вызов Python, сообщение очереди и внешний HTTP.
- Используйте имена из [карты архитектуры](./documents/architecture/index.md). Для нового шага укажите вход, выход, исходы и допустимое место в [сборке сценария](./documents/architecture/module-composition.md).
- Точки входа Python ведите в отдельном документе модуля по [единому шаблону](./templates/python-entry-point.md). В начале обзорной страницы разместите ссылку на контракт. Для компонента Runtime укажите, какую функцию вызывать для каждой задачи, со ссылкой на функцию во вложенном документе.
- Для HTTP-эндпоинта копируйте [единый шаблон](./templates/http-endpoint.md) в раздел модуля-владельца. Пишите метод и путь, вход, доступ, бизнес-логику, результат, ошибки и условия повтора. Открытые части отмечайте в плашке. Шаблон хранится вне публикуемых страниц.
- Перед именем функции или путём ручки ставьте `<span className="operation-badge operation-badge--async">ASYNC</span>` с тегом из [легенды контрактов](./documents/faq/index.md#теги-контрактов). Используйте наиболее конкретный тег операции, а для внутренних вызовов Python без тега инфраструктуры — `ASYNC` или `CALL`.
